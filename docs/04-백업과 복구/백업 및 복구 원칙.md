# 백업 및 복구 원칙

## 백업 영역

1. 소스와 Git 이력
2. Firestore 운영 데이터
3. Storage 객체
4. 배포 설정과 복원 절차

소스 복구 지점은 Firestore·Storage 백업을 대신하지 않는다.

## 데이터 변경 전 조건

- [ ] 대상 Firebase 프로젝트 확인
- [ ] 최신 백업 생성
- [ ] 백업 성공 및 무결성 확인
- [ ] dry-run으로 대상 건수 확인
- [ ] 예상 변경 전·후 값 검토
- [ ] 복원 명령과 담당자 확인
- [ ] 명시적인 실행 승인

## 복원 시험

- 운영 프로젝트에 바로 복원하지 않는다.
- 별도 복구 프로젝트 또는 격리 환경에서 먼저 시험한다.
- 문서 수, 핵심 관계, 파일 수와 대표 업무 흐름을 검증한다.
- 백업 성공과 복원 성공을 별개의 상태로 기록한다.

## Git 안전 원칙

- 기존 이력 삭제나 강제 푸시를 백업 방법으로 사용하지 않는다.
- bundle, 보존 태그, archive 브랜치와 외부 복구 지점을 사용한다.
- 원본 작업 트리가 dirty이면 격리 후보나 worktree에서 작업한다.
