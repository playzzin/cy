# 운영 원칙

## 우선순위

1. 서비스 중단 방지
2. 데이터 손실 방지
3. 급여·정산·권한의 정확성
4. 복구 가능성 확보
5. 작은 단위의 점진적 개선

## 실행 구분

### 바로 수행 가능

- 읽기 전용 조회와 집계
- 민감정보를 제거한 분석
- 격리 저장소의 코드 검토와 테스트
- 운영 데이터를 변경하지 않는 문서·보고서 생성

### 사전 검증 및 승인 필요

- Firestore·Storage 데이터 변경
- 급여·정산 확정
- 사용자 권한·직책 변경
- Rules·Functions·Hosting 배포
- GitHub 기준 브랜치 변경, 강제 푸시, 이력 재작성
- 파일·데이터 삭제

## 작업 완료 조건

- 요청 기간과 대상이 명확하다.
- 사용한 기준 데이터와 범위를 확인했다.
- 금액·건수·공수는 도구로 재검산했다.
- 변경 작업은 영향 범위에 맞는 테스트를 통과했다.
- 실패·생략·차단 항목을 성공으로 표현하지 않았다.
- 민감한 중간 파일과 임시 프로세스를 정리했다.
