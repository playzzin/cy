# CY 운영 안정화 실행 로드맵

> [!important] 실행 원칙
> 운영 서비스 중단과 데이터 손실 방지가 기능 개선보다 우선한다. 원본 dirty 작업 트리를 직접 정리하거나 덮어쓰지 않고, 격리 작업공간에서 테스트 우선으로 수정한다. 운영 데이터 쓰기·배포·삭제는 단계별 백업과 명시적 승인 전에는 수행하지 않는다.

## 목적

[[2026-08-30 출력일보 급여 조직변경 운영 위험 검토]]에서 확인된 위험을 순차적으로 제거하고, 읽기 전용 무결성 점검·백업·복원·회귀 테스트·운영 문서를 하나의 유지보수 체계로 정착시킨다.

## 역할 분담

- **Hermes:** 총괄, 위험 분류, 단계 승인선 관리, 실제 검증, 결과 통합
- **Codex CLI:** 격리 작업공간에서 테스트 우선 코드 구현·검토 보조
- **Obsidian:** 요구사항, 의사결정, 실행 기록, 검증 결과, 운영 런북의 단일 지식 기준
- **사용자:** 운영 데이터 변경·배포·삭제 단계의 최종 승인

## 공통 완료 조건

모든 코드 변경은 다음을 만족해야 한다.

1. 재현 테스트가 먼저 실패한다(RED).
2. 최소 수정으로 테스트를 통과시킨다(GREEN).
3. 관련 회귀 테스트와 8GB 힙 typecheck를 통과한다.
4. Functions build, 프로젝트 전체 검증, production build를 단계 위험에 맞게 수행한다.
5. 운영 데이터 변경이 있으면 백업, dry-run, 대상 건수, 전후 값, 복원 시험을 확인한다.
6. 원본 작업 트리에 섞지 않고 변경 diff를 별도 검토한다.
7. 배포는 별도 승인 없이는 수행하지 않는다.
