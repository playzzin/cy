## 확인된 P0/P1

### P0 — reviewed 저장본과 화면·출력 불일치

`reviewed` 상태는 일반 저장이 차단되어 사실상 검토 완료 snapshot이지만, 저장 snapshot 적용 predicate는 `confirmed`와 `paid`만 포함한다. 그 결과 reviewed 이후 master·일보·가불·설정이 변경되면 화면, 마감표, 명세서 및 이체 대상 계산이 저장 당시 값이 아닌 live 재계산 값으로 바뀔 수 있다.

관련 경로:

- `src/services/monthlyPayrollSettlementService.ts`
- `src/pages/payroll/MonthlyWageDraftPage.tsx`
- `src/services/statementOutputService.ts`
- `src/types/statementOutput.ts`

추가 위험:

- 같은 payment ID의 복수 저장본이 있으면 명시적 revision 비교 없이 후행 항목이 덮을 수 있다.
- 재발행은 기존 발행 snapshot을 읽어 별도 revision으로 남기지 않고 같은 output 문서를 merge 갱신한다.

### P0 — 음수 공제·환급 부호 소실

입력과 월 가불대장 계산 일부는 signed 값을 유지하지만 다음 경계에서 부호가 사라진다.

1. legacy 명시 필드가 음수일 때 `> 0` fallback 때문에 0으로 해석될 수 있음
2. 급여 저장·마감 행에서 `Math.max(0)`으로 총공제를 0 이상으로 clamp
3. 명세서 XLSX에서 `Math.abs` 후 음수 표시를 강제하여 환급을 차감으로 뒤집을 수 있음

그 결과 저장 snapshot에서 `gross - deduction = net` 불변식이 깨지거나 XLSX 왕복 후 실지급 표시가 달라질 수 있다.

관련 경로:

- `src/pages/payroll/utils/advanceLedgerInput.ts`
- `src/pages/payroll/components/MonthlyAdvanceLedger.tsx`
- `src/pages/payroll/MonthlyWageDraftPage.tsx`
- `src/pages/payroll/utils/payslipWorkbook.ts`

### P1 — 최신 0원 가불 정정본이 과거 큰 금액에 밀림

현재 후보 선택과 upstream dedupe가 최신성보다 금액 크기를 우선한다. 동일 scope의 최신 0원 정정본이 있더라도 과거 큰 금액이 선택될 수 있다.

관련 경로:

- `src/pages/payroll/utils/advanceLedgerInput.ts`
- `src/pages/payroll/MonthlyWageDraftPage.tsx`

### P1 — 팀 없는 legacy 가불의 복수 scope 소비

팀 scope가 없는 legacy 가불은 각 급여 행이 독립 fallback으로 선택한다. 팀 이동 또는 복수 급여형태가 있으면 같은 legacy 한 건이 여러 scope에 중복 반영될 수 있다.

권장 정책:

- exact scoped record 우선
- legacy가 오직 하나의 eligible payroll scope에만 대응할 때만 fallback
- 둘 이상이 경쟁하면 양쪽 모두 자동 귀속하지 않고 수동 귀속 대기로 fail-closed

## strict TDD 구현 순서

1. **reviewed snapshot source 일치**
   - reviewed/confirmed/paid는 저장 snapshot 사용
   - draft만 live 사용
   - malformed/missing reviewed snapshot은 live fallback 금지
   - 중복 payment ID 선택을 deterministic하게 고정
2. **명세서 재발행 불변 revision**
   - 최초 발행 snapshot 보존
   - 재발행은 저장 snapshot을 source로 별도 revision 생성
3. **음수 부호 end-to-end 보존**
   - normalize → aggregate → settlement snapshot → XLSX round-trip
   - `gross - deduction = net` 불변식 검증
4. **최신 정정본 우선**
   - 동일 canonical scope에서 최신 0원 정정본 선택
   - timestamp/revision 불명확 시 큰 금액 임의 선택 금지
5. **legacy 단일 소비**
   - 복수 scope 경쟁 시 자동 귀속 금지 및 수동 귀속 대기
6. **중복 급여 행과 draft revision 충돌**
   - 팀·급여형태 변경 이후 중복 행 방지
   - 동시편집 conflict 검출

- resolver (`monthlyPayrollSnapshot.ts` 206–244, 249–250): 선택 scope의 teamId가 공백이거나 `__`를 포함하면 즉시 fail-closed. 유효하면 `isSettlementInScope`로 해당 팀 settlement만 검증한다
- 타팀 손상 격리 테스트 (`monthlyPayrollSnapshot.test.ts` 307–353): 한 팀 정상 + 다른 팀 malformed payload일 때 정상 팀 선택은 diagnostics 없이 통과하고, 손상 팀 선택과 전체 조회만 fail-closed
- 별칭 정규화 (356–390): legacy teamId를 canonical로 맞춘 뒤 선택 팀과 비교한다
- 잘못된 선택 scope `''` / 공백 / `team__invalid` (393–407): all-team으로 완화하지 않고 fail-closed
- 선택 범위 안 공백 teamId·canonical identity 불일치 (410–424): 계속 fail-closed. 무관 팀 payload 차단이 아니라 선택 팀 메타데이터 손상 차단이다. `canonicalizeTeamIdForScope`가 null이면 그 settlement를 선택 범위에 남겨 validator로 막는다
