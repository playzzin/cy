# CY 프로젝트 개선 결과

점검 범위는 이번 감사에서 확인한 팀 등록 오류, 숙소 원장 실패 처리, 공공요금 부분 저장, 브라우저 AI 키, 미완성 화면, 자동 검사 누락, 큰 화면 코드 및 불필요한 파일이다. 기존 작업을 유지한 채 로컬 코드에 반영했다. 운영 배포와 실제 업무 데이터 변경은 하지 않았다.

## 반영 내용

| 순서 | 문제 | 개선 결과 |
| --- | --- | --- |
| 1 | 팀명·팀구분·팀장명 헤더 혼동 | 정확한 별칭으로 열을 구분하고 중복 열·팀명·불명확한 팀장/회사/상위팀을 저장 전에 검증한다. 관계 ID를 저장하며 재시도에서는 성공한 행을 제외한다. |
| 2 | 청구 대상 조회 실패가 빈 목록으로 바뀜 | 조회 오류를 상위 화면에 전달한다. 실패한 조회를 근거로 임대료 행을 만들어 내지 않는다. |
| 3 | 공공요금 여러 건 저장 중 부분 성공 | 전체 행의 월·숙소·금액을 먼저 검사하고 한 번의 Firestore 배치로 저장한다. 500건 초과 요청은 쓰기 전에 거부한다. |
| 4 | Gemini 키가 브라우저에 저장·전송됨 | 일반 문서·이미지·도면·에이전트·세금계산서·인력 검색을 인증된 서버 함수로 옮겼다. 서버 모델 선택, 사용자별 동시 요청·일일 한도, 시간/크기 제한을 적용한다. 서버 성공 후 과거 브라우저 키를 지운다. 빌드에서도 과거 AI 환경변수를 제외한다. |
| 5 | 월급제 지급 화면과 원장 Excel 버튼이 미완성 | 월급제 지급을 기존 계산·출력 화면에 연결하고 누락 경로를 연결했다. 탭은 주소에 남기며 조회 도구를 유지한다. 원장 Excel은 현재 검색 결과를 실제 파일로 내보낸다. 이전 조회 응답과 조회 실패로 인한 잘못된 내보내기를 막는다. |
| 6 | 서버 테스트 일부만 자동 실행 | 서버 테스트 파일 전체를 자동 발견하고 CI에서 실행한다. 신규·분리 모듈에는 미사용 코드 및 Hook 의존성 검사를 적용한다. 시공계획서 테스트의 비동기 삭제 버튼 대기를 수정했다. |
| 7 | 큰 화면에 계산·출력·스타일 집중 | 원장 계산 모델, 월급 계산 모델·스타일, 지원 현장 계산 모델·명세서 패널을 별도 파일로 분리했다. 기존 내보내기 API는 유지한다. |
| 8 | 추적 중인 진단 산출물·미사용 코드와 의존성 | 진단 파일 27개와 미사용 코드 3개를 로컬 백업으로 이동했다. 미사용 UI 패키지 및 타입 패키지 4개와 Functions의 루트 앱 의존성을 제거하고 lockfile을 갱신했다. 임시 검증 파일 제외 규칙을 추가했다. |

## 검증

- 최종 React 전체: 389개 테스트 파일, 2,386개 통과, 기존 2개 건너뜀. 원장 조회/Excel, 급여 탭, AI 파서 및 원장 계산 회귀 검증을 포함한다.
- 서버 전체: 69개 테스트 파일을 발견, 386개 통과, 8개 건너뜀. 건너뛴 검사는 에뮬레이터 등 별도 조건이 필요한 검사다.
- 앱 타입 검사, 앱 최종 빌드, Functions 빌드 통과. 변경한 앱 파일의 lint 및 강화한 모듈 검사 통과.
- Hosting 산출물 검사 통과. 빌드 파일 489개에서 시험용 AI 키의 잔존 여부를 검사해 0건임을 확인했다. 이번 빌드는 `demo-cy-quality` 검증 환경으로 만든 것이므로 운영 배포용으로 사용하지 않는다.
- 빌드 환경 및 배포 기록 관련 검사 9개 통과.
- 실제 브라우저: 운영 서비스와 분리한 `demo-cy-quality` 로컬 환경에서 팀 열 매핑·중복 열 등록 차단, 월급제 경로 전환·탭 선택·기간 변경·조회 도구, 지원 현장 화면 표시와 빈 원장의 다운로드 차단을 확인했다. 검증 후 임시 서버와 탭을 종료했다.
- Excel 테스트는 합성 데이터로 실제 XLSX 바이트를 생성하고 금액 부호, 합계 및 앞자리 0이 있는 식별자를 검사한다.

## 운영 반영 시 필요한 사항과 검증 한계

- 새 `geminiGateway` 서버 함수를 먼저 배포하고 서버 AI 설정을 확인한 뒤 웹을 배포해야 한다. 서버가 없는 상태에서 새 웹만 배포하면 AI 기능은 업데이트 안내와 함께 실패한다. 실제 공급자 호출·과금 및 운영 계정별 권한은 이번 로컬 검증에 포함하지 않았다.
- Google Drive Picker는 Gemini 키 재사용을 중단했다. 사용할 경우 Drive 전용으로 제한한 `REACT_APP_GOOGLE_DRIVE_API_KEY`와 기존 OAuth 설정이 필요하다.
- 과거 배포 파일에 포함됐던 키의 회수·교체는 별도 운영 조치다. 이번 변경은 새 빌드에 키가 들어가지 않도록 한다.
- Firestore 원자성은 배치 API와 실패 경로 테스트로 검증했다. 실제 운영 저장 및 숙소 배치 전용 에뮬레이터 검사는 실행하지 않았다.
- 큰 화면의 책임을 분리했지만 원장 및 월급 화면의 본문은 여전히 크다. 남은 모든 UI를 한 번에 재작성하지는 않았다. 이번에 분리한 모듈부터 정적 검사를 강화했다.
- 기존 작업 중인 기능과 별도 배포 작업 폴더는 유지했다. Git 이력 안의 과거 진단 파일까지 지우는 이력 재작성은 하지 않았다.

## 로컬 증거와 복구

작업 전 코드 스냅샷은 `tmp/cy-project-improvements/baseline/`, 이동한 파일은 `tmp/cy-project-improvements/archived/`에 있다. 백업 목록의 SHA-256과 원래 경로는 `archived/inventory.json`에 기록했다. 테스트·lint·빌드 로그도 같은 상위 폴더에 보관한다. 이 폴더에는 기존 코드가 포함되므로 저장소에 추가하지 않는다.

최종 검증 로그: `app-final.log`, `functions-all.log`, `types-final.log`, `lint-touched.log`, `lint-final.log`, `functions-build-final.log`, `build-final.log`, `build-guard-tests.log`. 최종 코드와 빌드 기록의 소스 지문도 일치한다.
