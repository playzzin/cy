# 2026-09-01 CY 기술 스킬 및 최신정보 기준선

## 결론

권고는 **즉시 운영 적용 금지, 슈퍼돼지 검토 대기**. Phase 2 출력일보 코드 후보는 공식 Firestore 원자성·Rules 제한과 대체로 같은 방향을 따르지만, Rules Emulator 행위 테스트가 없고 scope 단독 변조 결합이 불완전하다. Phase 3 급여 `paymentSnapshot`·재발행 revision은 조사·일부 테스트가 진행 중이며 배포 가능 상태가 아니다.

- 공식 Firestore는 transaction/batched write를 전부 성공 또는 전부 실패로 보장하고, Rules는 `getAfter()`로 커밋 전 결합을 강제한다.[2][3]
- 공식 access-call 한도는 단건/쿼리 10회, transaction·batched write 전체 20회이며 표현식은 요청당 1,000개다.[1][3]
- CY 앱은 React 18.3.1·TypeScript 5.6.3 strict·Functions Node 22를 쓴다. 2026-09-01 공식 npm 레지스트리 최신값은 React 19.2.8·TypeScript 7.0.2·Firebase JS 12.18.0이며, 이번 안정화 범위에서는 업그레이드하지 않는다.[15][16][19]
- 고대리 기본 스킬은 `cy-project-research-support` + `grounded-citations` + `obsidian`이다. TDD·리뷰·GitHub 스킬은 이과장 구현 단계용이며, 외부 커뮤니티 스킬은 설치하지 않는다.

상태: **검토 대기**. 승인·적용은 슈퍼돼지/이과장 절차 이후에만 기록한다.

## P0 / P1 / P2 권고

### P0 — 즉시 적용하지 말고 차단·검증

1. **운영 Scope Protocol activation 금지.** 코드 후보와 단위 테스트는 있어도 Rules Emulator allow/deny가 없다. 정적 Rules 검사는 배포 조건을 대체하지 않는다.[7][8]
2. **출력일보 client mutation을 trusted server callable로 옮기거나, 사장님 명시 위험 승인 전에는 activation하지 않는다.** 기존 Phase 2 검증 문서와 동일.
3. **급여 `reviewed` 저장본과 화면·출력 일치, 재발행 revision, 부호 보존.** Rules는 reviewed 이후 본문 덮어쓰기를 막지만, 앱이 live 재계산을 섞으면 사용자에게는 변경된 것처럼 보인다. 구현은 이과장 TDD, 고대리는 코드 적용하지 않음.
4. **테스트 통과와 배포 가능을 동일시하지 않는다.** 공식 문서는 Rules를 Emulator에서 검증하라고 한다.[7][17]

### P1 — 슈퍼돼지 승인 후 격리 구현

1. Functions `firebase-admin` 11과 앱 13 불일치 정리. 운영 배포 없이 후보에서 호환 매트릭스만.
2. Functions `strict: false` / TypeScript 4.9를 앱 5.6 정책에 맞출지 결정. 업그레이드 시 신규 타입 오류가 날 수 있다.[12]
3. `react-hooks/exhaustive-deps` off 재검토. Phase 2 request identity가 Effect 의존성 누락으로 깨질 수 있음.
4. 급여 snapshot을 Zod 또는 동등한 단일 런타임 스키마로 고정. 현재 커스텀 validator는 존재하나 출력일보 Zod 경계와 불균일.
5. Firebase JS 12.6 → 12.18은 동일 메이저 내 minor 상승이다. 격리 `verify:project`와 호환 검토 후에만. 이번 세션에서는 실행하지 않음.[15]

### P2 — 보류·재확인

1. React 19. 최신 안정은 19.2.8이다. CRA 5·Refine 4·테스트 라이브러리 14와의 호환은 미검증이므로 업그레이드하지 않는다.[16]
2. TypeScript 컴파일러 업그레이드. 공식 npm 최신은 7.0.2이고 5.9 릴리스 문서는 존재하지만, CY 5.6.3 및 Functions 4.9와의 단계별 호환 검증이 없다.[13][19]
3. Cloud Functions Node 24/26. GCP 표에는 있으나 Firebase Functions 지원 목록에는 22/20/18만 있다.[5][6]
4. 앱 전역 Playwright/Cypress E2E 스킬 설치. 필요 후보만 보류.

## 위험·호환성·미검증

- **데이터 무결성:** transaction은 전부 적용 또는 전부 실패다.[2] 여러 WriteBatch를 이어 붙이면 배치 사이는 원자성이 없다. activation·대량 정리는 재실행 가능해야 한다.
- **보안·권한:** `getAfter()`/`existsAfter()`는 한도와 과금 대상 읽기다.[3] `firestore.rules` 소스 약 76,563바이트는 256KB 소스 한도 안이다.[1] 컴파일 후 250KB 한도는 미검증. 표현식 1,000 한도도 정적 파일 검사만으로는 미검증.
- **버전 호환성:** 앱 Node 생태계(react-scripts 5)와 Functions Node 22는 다른 런타임이다. Node.js 자체는 22가 LTS, 20은 2026-03-24 EOL이다.[14] Firebase Functions Node 20 decommission은 2026-10-30로 표기되어 CY Functions(22)와는 별개다.[6]
- **운영·rollback:** 공식 복구는 managed export/import이며 결제 프로젝트와 GCS가 필요하다.[9] Vault `백업 및 복구 원칙`은 운영 직접 복원 금지·격리 시험과 같다. 레거시 daily-report 마이그레이션 스크립트는 fail-closed.
- **미검증:**
  - Rules Emulator에서 getAfter/scope/payroll 불변의 실제 allow/deny
  - 컴파일된 ruleset 크기
  - 요청당 표현식 1,000 실측
  - JS API의 쓰기 500과 quotas 페이지 표의 관계. quotas 페이지 열람분에는 “문서 쓰기 500” 행이 보이지 않고 field transformation 500·요청 10MiB가 있다.[1][4] 커뮤니티의 “500 해제” 주장은 미검증이므로 CY는 400 상한을 유지
  - TypeScript 7.0의 공식 핸드북 릴리스 노트 URL은 2026-09-01 열람 시 404였다. npm 최신값 7.0.2와 상세 변경 문서의 정합성은 추가 확인 필요[19]
  - React 18.3.1 보안 패치 필요 여부. 공식 최신 라인은 19.x[16]
  - Emulator와 프로덕션 Rules 평가 차이
