# 팀장 경비 신청과 사무실 승인

팀장 직책의 `경비관리 > 경비입력`에서 현재 소속팀을 사용팀으로 표시하고, 비용을 부담할 청구팀을 별도로 선택한다. 소속팀이 여러 개인 경우 연결된 팀 안에서 사용팀을 선택한다. 사용일, 경비 구분, 금액, 결제수단과 영수증을 제출한다. 사무실은 `경비 승인`에서 확인한다. 관리자는 `운영 관리 > 팀장 경비 승인`에서도 처리할 수 있다.

## 반영 기준

- 제출 상태는 승인 대기이며 경비 원장과 팀 정산에 반영하지 않는다.
- 승인 시 현재 소속인 사용팀을 `payerTeamId`, 선택한 청구팀을 `chargeToTeamId`로 설정한 `teamCharge` 원장을 한 건 생성한다. 기존 정산 계산이 청구팀의 경비 차감과 사용팀의 선지급금 환급을 각각 만든다. 두 팀이 같은 경우에만 해당 팀의 순정산 증감은 0원이다. 기존 단일 팀 신청은 그 팀을 사용팀·청구팀으로 유지한다.
- 환급은 정산의 추가 항목이며 실제 은행 송금을 실행하지 않는다.
- 반려는 사유를 필수로 남기고 원장을 생성하지 않는다.
- 본인 신청 승인, 비활성 계정, 소속팀이 아닌 팀을 사용팀으로 바꾸는 요청을 서버에서 차단한다. 청구팀 선택용으로 팀 이름·색상·아이콘만 제공한다. 동일 승인 재시도는 원장을 추가 생성하지 않는다.

## 영수증과 팀 표시

사진 촬영, 파일 첨부, 파일 드래그 등록을 지원하며 같은 첨부 목록과 제한을 사용한다. 촬영은 후면 카메라를 우선 요청하고 JPEG로 첨부한다. 카메라 대화상자를 닫거나 페이지를 떠나면 미디어 스트림을 종료한다. 기기 카메라 파일 선택도 제공한다. 사용팀과 청구팀의 색상은 팀 관리에 저장된 색상을 사용하며 입력, 신청 내역, 승인 확인 창에 표시한다.

팀 아이콘은 팀 관리의 `iconKey` 또는 `icon`을 공통 아이콘 매핑으로 표시하고, 미등록 값은 기본 팀 아이콘을 사용한다. 신규 신청은 아이콘도 함께 보관하고 기존 신청은 현재 팀 목록에서 보완한다.

## 영수증 분석과 등록 전 확인

첫 영수증 첨부 시 `teamExpenseRequests`의 `analyze` 동작으로 Gemini 분석 미리보기를 연다. 추가 첨부는 같은 경비의 증빙이며 각 파일의 미리보기에서 선택한 한 건만 분석한다. 여러 거래의 금액을 임의 합산하지 않는다.

서버 AI 설정의 API 키와 `documentModel`을 사용하며 키는 브라우저로 전달하지 않는다. [Gemini 구조화 응답](https://ai.google.dev/api/generate-content)을 사용해 사용일·원화 최종 결제금액·결제수단·현재 등록된 경비 구분만 추출한다. API 제한시간은 75초이며 사용자별 분당 10회·일일 100회로 제한한다. 분석 파일이나 원문은 서버에 따로 보관하지 않고 사용량만 비공개 `server_settings` 문서에 기록한다.

미확인 값, 외화 금액, 취소 전표 또는 여러 거래는 추측해 입력하지 않는다. 카드 결제는 개인카드 선지급 여부를 확인하도록 안내한다. 원본과 분석 항목을 함께 표시하고 사용자가 수정한 후 적용한다. 분석 실패 시 직접 입력하거나 재분석할 수 있다. 분석을 닫아도 작성 중인 입력은 유지한다.

`등록 전 미리보기`에서 팀·사용일·금액·결제수단·경비 구분·영수증을 확인한 다음 `확인 후 승인 요청`을 눌러야 업로드와 제출을 실행한다. AI 분석 자체는 신청이나 경비 원장을 생성하지 않는다.

## 메뉴 등록

`node scripts/register-team-expense-menu.cjs`로 미리 보고 `--apply`로 적용한다. 통합메뉴 `settings/menus_v12`의 직책 설정에서 대상 메뉴를 찾는다. 기존 화면은 하위 메뉴로 보존하며 부모의 중복 경로는 제거한다. 적용 직전 메뉴는 `.codex-team-expense-request/menu-before-*.json`에 백업한다. 반복 적용해도 중복 메뉴를 만들지 않는다.

## 보호 및 운영

새 신청과 영수증은 인증된 서버 함수 `teamExpenseRequests`를 통해서만 기록한다. 직접 데이터베이스/저장소 읽기와 쓰기는 규칙에서 차단한다. 첨부는 JPG/PNG/WEBP/PDF, 최대 5개, 개당 5MB이며 제출 후 변경할 수 없다. 동일 파일의 재시도는 기존 영수증을 반환한다. 미제출 임시 신청과 첨부는 마지막 사용 후 30일이 지나면 사무실의 정리 대상으로 표시한다. 사무실에서 대상을 조회하고 건별 삭제를 확인해야 삭제한다. 서버가 삭제 직전에 기간과 상태를 다시 검사하며 제출·승인·반려 자료는 제외한다. 중간 실패는 재시도할 수 있다. 예약 자동 삭제는 실행하지 않는다.

서버는 업로드 전에 신청당 최대 5개의 파일 ID를 트랜잭션으로 예약하여 동시 업로드로 제한을 넘지 못하게 한다. 비활성·퇴사 작업자의 소속 연결은 신규 신청 권한으로 사용하지 않는다. 승인 시 사용팀·청구팀의 존재를 검사하고, 승인 재시도 시 기존 경비 원장의 신청 연결을 재확인한다. 원장이 삭제된 경우 자동 재생성하지 않고 확인 오류를 반환한다. 금액에 배열·불리언·객체를 넘겨 숫자로 강제 변환하는 입력은 거부한다.

승인은 신청 상태 변경과 경비 원장 생성을 하나의 트랜잭션에서 수행한다. 승인 완료 원장을 기존 경비관리에서 수동 수정하면 신청 화면의 원본과 달라질 수 있으므로 승인 내역을 대조한다.

## 검증

신청 목록은 서버에서 신청자와 조회 월을 함께 제한한다. 과거 신청이나 영수증 업로드 중인 자료가 누적되어도 다른 월의 조회 한도를 소비하지 않는다. 한 번에 100건씩 이어서 조회하며 한 달 2,000건 제한을 제거했다. 화면의 필터와 합계는 불러온 항목에만 적용한다. 조회 중 추가된 신청은 새로고침으로 확인한다.

기존 경비 조회 서비스는 승인 원장의 `sourceRequestId`와 영수증 연결을 유지한다. 개발용 샘플 계정에서는 실제 경비 서버를 호출하지 않고 실제 계정 로그인 안내를 표시한다.

운영 대조는 `node scripts/audit-team-expense-requests.cjs`로 실행한다. 신청·승인 원장을 읽기만 하며 개인정보나 금액 대신 상태별 건수, 누락, 불일치, 중복 건수만 출력한다. 운영 신청이 0건이면 실제 등록 성공을 증명한 것으로 해석하지 않는다.

화면 테스트는 팀 선택·첨부·제출·실패 후 재시도·승인·반려를 검증한다. 서버 테스트는 로컬 Firestore/Storage 에뮬레이터에서 동적 직책, 권한, 영수증 불변성, 응답 유실 후 재시도, 동시 승인, 반려 및 같은 팀의 차감/환급 연결을 검증한다. 메뉴 등록 테스트는 기존 경로 보존과 멱등성을 검증한다. 운영 데이터에 테스트 경비를 만들지 않는다.
