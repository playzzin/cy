# ADR-001 안전한 Git 재기준화

## 문제

운영 소스, 로컬 빌드, 과거 배포 복제본, 여러 worktree와 미커밋 변경이 함께 존재하면 어느 상태가 운영 기준인지 불명확해진다.

## 결정

GitHub 이력을 초기화하지 않는다. 기존 이력과 사용자 작업을 보존하고, 격리 후보에서 현재 상태를 검증한 뒤 새로운 기준 브랜치와 태그를 비파괴적으로 추가한다.

## 필수 절차

1. 원본 Git 상태와 변경 파일 기록
2. Git bundle, binary patch, 신규 파일, SHA-256 복구 지점 생성
3. 원본과 분리된 후보 저장소 또는 worktree 구성
4. 기능·금액·권한 위험 검토
5. 타입체크, 테스트, Functions 빌드, 앱 빌드, Hosting 검증
6. 운영 데이터 백업 및 복원 가능성 확인
7. 새 후보 브랜치와 보존 태그 먼저 push
8. 승인 후에만 기준 브랜치 또는 운영 배포 결정

## 금지

- 검증 전 `.git` 재생성
- 원격 강제 푸시
- 운영 배포본을 근거 없이 현재 소스와 동일하다고 가정
- dirty 원본에서 대규모 정리
