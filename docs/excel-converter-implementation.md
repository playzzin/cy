# 엑셀 대화형 변환 구현·검증 기록

작성일: 2026-09-30 (한국 시간)

## 반영한 기능

1. 결과마다 계획, 부모 버전, 적용 요청, 해당 분기의 대화, 직접 수정과 원본 대응 정보를 보관한다. 변경 비교에서 값 변경과 행 이동을 구분하고, 변경·근거·문제에서 문서 위치로 이동한다.
2. 설명 질문은 로컬의 결과·원본·수식 근거로 응답하고 새 결과를 만들지 않는다. 설명에 표시한 실제 원본 값은 이후 AI 대화 문맥에 넣지 않는다. 현재 정렬·필터·합산·분리·고정값·직접 수정 조건을 표시한다.
3. ‘이 결과부터 수정’으로 과거 결과의 계획과 대화를 기준으로 새 결과를 만든다. 이후 결과도 계속 비교·다운로드할 수 있다.
4. ‘이 기기에 작업 보관’을 켜면 입력 파일·대화·버전을 브라우저 IndexedDB에 저장한다. 1일·7일·30일 보관, 작업명, 저장 상태, 보관본 열기·삭제, 만료 정리, 저장 실패 안내, 저장 전 이탈 안내를 제공한다. 계정 변경 시 작업 화면을 초기화하고 계정별 저장 키를 분리한다.
5. 결과 셀과 행을 선택해 범위를 지정한다. 명확한 값 교체 요청과 직접 입력을 지원한다. 수정은 원본 행 기준으로 추적하므로 정렬 후에도 같은 사람의 값에 적용된다. 필터로 잠시 제외했다 복원한 인원의 수정도 유지한다. 개인별 위임장의 고정 위치도 수정할 수 있다.
6. 날짜·금액·백분율·앞자리 0·줄바꿈 표시를 개선했다. 수식 입력칸은 보호하고, 직접 수정한 입력값에 따른 재계산은 원본 금액과의 차이를 경고로 안내한다. 모바일 대화/미리보기 전환과 넓은 화면의 영역 너비 조절을 제공한다.

## 사용 방법

원본과 양식을 첨부한 뒤 첫 결과를 만든다. 결과에서 칸을 선택하면 아래 ‘원본 근거’가 열린다. 여기서 새 값을 입력하거나, 대화에 ‘이 칸을 서울로 바꿔줘’처럼 요청한다. 행 선택은 ‘주소를 서울로 바꿔줘’처럼 항목을 함께 지정한다. 선택한 범위는 입력창 위에서 해제할 수 있다.

과거 결과를 보기만 하는 동안 일반 요청은 표시된 수정 기준에 적용된다. ‘이 결과부터 수정’을 누르면 수정 기준도 그 버전으로 바뀐다. 결과의 선택한 셀을 수정할 때는 그 셀이 있는 버전을 기준으로 새 결과를 만든다.

## 실제 브라우저 검증

대상은 `http://localhost:3000/tools/excel-converter`, 데이터는 저장소의 가상 예시다. AI 계획 응답만 브라우저에서 대체하고 실제 앱 화면·변환 엔진·파일 다운로드·IndexedDB는 그대로 사용했다.

- 셀 선택 → 설명 질문: 버전 수가 늘지 않고 실제 원본 행 근거가 표시됨.
- 주소 직접 수정 및 ‘이 칸을 서울로 바꿔줘’: 선택한 칸만 새 결과에 반영됨.
- 보관 → 새로고침 → 작업 열기: 수정 주소, 버전, 대화 복원.
- 결과 1에서 새 분기: 결과 2의 수정 주소는 남으며 새 분기는 결과 1의 원래 주소로 시작.
- 저장 단계에 가상 용량 부족 오류 주입: 실패 표시, 이전 결과 유지, 오류 제거 후 재저장 성공.
- 원본 위치 보기: 결과의 주소 칸에서 원본 `D5`로 이동, 기존 결과 선택 해제.
- 390px 모바일: 가로 넘침 없음, 대화/미리보기 전환, 과거 버전 다운로드 가능. 검토를 펼쳐도 문서 영역 높이를 유지함.
- 내려받은 파일을 별도 XLSX 읽기 도구로 재검사: `B7=서울 테스트로 123`, `E13=1270000`, `E7=C7*D7`, 병합 32개 유지.
- 확인 시 브라우저 콘솔 오류 0개.

근거 파일: `outputs/excel-converter/chat-validation/`의 `synthetic-matrix.json`, `browser-result.xlsx`, `desktop-review.png`, `mobile.png`, `build.log`.

## 성능 측정 범위

가상 3인 파일 20개 조합의 로컬 읽기·작성·검사·재읽기 시간을 `synthetic-matrix.json`에 기록했다. 최종 실행 중앙값 187ms, 상위 95% 지점 289ms다. 이 수치는 AI 대기시간, 대용량 성능, 운영 환경의 지연시간을 대표하지 않는다. 브라우저에서 여러 결과 버전을 열었을 때 관찰한 JS heap은 약 44MB였으며, 앱 전체를 포함한 한 번의 관측값이다.

## 사용자 경험 추가 개선 (2026-09-30)

- 저장 설정을 ‘보관함·설정’으로 정리하고 작업명·보관 여부·저장 상태를 우선 표시한다. 저장 실패 시 동일한 작업을 다시 저장할 수 있다.
- 첫 변환 전의 첨부와 작성 중인 요청도 보호한다. 새 대화·파일 교체 등에서 ‘보관하고 계속’은 저장 성공 후에만 이동한다. 예시 파일을 불러와도 먼저 작성한 요청을 유지한다.
- 미리보기의 수정 기준·이전 결과에서 이어가기·다운로드를 한 영역으로 정리한다. 과거 결과를 보기만 할 때와 그 결과의 셀을 선택했을 때 수정 기준을 정확하게 안내한다.
- 다운로드 경고를 누르면 구체적인 문제와 위치를 확인할 수 있다. 이곳에서 확인한 결과만 내려받을 수 있고, 확인 여부는 버전마다 보관한다.
- ‘무엇이 달라졌어?’에는 실제 값 변경·행 이동·추가·제외를 설명한다. 경고와 제외 이유 질문도 해당 결과를 근거로 답한다. ‘수정하고 보여줘’는 설명으로 오인하지 않는다.
- 직접 수정에서 값이 같으면 적용을 막고, 아직 적용하지 않은 변경과 잘못된 날짜를 안내한다. 로컬 수정은 실제 처리에 맞는 진행 문구를 사용한다.
- 모바일에서 완료 알림의 ‘결과 보기’로 이동하고, ‘대화로 수정하기’로 입력창에 돌아온다. 요청 중에는 이전 완료 알림을 지운다.

추가 브라우저 검증 역시 가상 예시와 대체 AI 계획 응답을 사용했다. 다음은 실제 앱·저장소·변환 엔진에서 확인했다.

1. 첫 변환 전 파일 2개와 요청 초안 보관 → 새 대화 → 보관함에서 초안과 첨부 복원.
2. 단가 `180000 → 190000` 수정 → 다운로드 잠금 → 재계산 경고 열기 → 확인 → 다운로드. 별도 XLSX 읽기 결과는 `D7=190000`, `E7=665000`, `E7` 수식 `C7*D7`, `E13=1305000`, 병합 32개다.
3. 변경 질문이 단가·계산 금액·합계의 실제 세 가지 차이를 설명하고 버전은 추가하지 않음.
4. 과거 결과를 선택하면 최신 결과에 적용된다는 안내가 보이고, 해당 결과의 셀을 선택하면 미리보기와 입력창 모두 선택 버전을 수정 기준으로 안내함.
5. 390px 모바일에서 가로 넘침 없음. 완료된 결과 4로 이동하고 대화 복귀 시 입력창에 초점이 놓임. 보관 설정이 화면 너비 안에 표시되고 Escape로 닫힘.
6. IndexedDB 저장에 용량 부족 오류 주입 → 실패 안내 → 오류 제거 → ‘저장 다시 시도’ 성공. 새로고침 후 결과 4개와 수정된 단가 복원.

근거 파일은 `outputs/excel-converter/ux-validation/`의 `desktop-review.png`, `mobile-preview.png`, `recalculated-result.xlsx`, `build.log`다. 검증용 보관본은 정리했으며 AI 응답 대체도 해제했다. 이후 실제 Gemini와 Microsoft Excel 검증은 다음 절에 기록한다.

## 실제 AI·Microsoft Excel 추가 검증 (2026-09-30)

브라우저에서 응답을 대체하지 않고 실제 Firebase 분석 기능과 설정된 `gemini-3.8-flash`를 사용했다. 사용 자료는 저장소의 가상 예시이며, 실제 사용자 원본이나 개인정보는 전송하지 않았다.

- 노임명세서 한 작업에서 최초 변환과 10회 후속 수정을 수행했다. 이름 정렬, 주소 고정, 2공수 미만 제외, 현장명 변경, 서명 공란, 인원 복원, 원본 주소 복원을 확인했다. 관련 없는 정렬·고정값·필터가 유지됐으며 최종 3명·7공수·1,270,000원이 맞았다.
- ‘전체 인원을 복원해줘’가 제외 조건 추가로 잘못 차단되는 문제를 재현하고 수정했다. 실제 같은 요청 재시도와 회귀 검사에서 정상 복원됐다. 개별 작성으로 합산을 해제하는 판정도 같은 원칙으로 보완했다. 요청하지 않은 새 제외·합산은 계속 차단한다.
- 공통 현장명을 정렬 전 첫 사람의 값으로 식별해 가짜 추가·제외로 표시하던 문제를 수정했다. 공통 칸은 문서 기준으로, 개인별 양식은 사람 기준으로 비교한다. 실제 재검증에서 ‘행 이동 2행’만 설명하며 현장명은 유지됐다.
- 양식 기억을 비운 뒤 개인별 위임장, 새로운 세 줄 양식, 병합 노임명세서의 구조 분석부터 실제 AI를 호출했다. 위임장은 3개 파일, 새 양식은 3명·9공수·1,540,000원이며 마지막 계좌의 앞자리 0도 유지됐다.
- 실제 기능 호출 응답 22개를 관찰했다. 여기에는 복원 오류 수정 전 자동 보정과 재시도가 포함된다. 서버가 응답에 기록한 시간의 중앙값은 8,344ms, 상위 95% 지점은 19,066ms다. 재사용 응답 메타데이터가 포함될 수 있으며 전체 화면 대기시간이나 일반적인 AI 정확도를 의미하지 않는다.

Microsoft Excel 16.0의 별도 비표시 인스턴스에서 매크로·외부 연결 실행을 끄고 가상 파일을 읽기 전용으로 열었다. 재계산한 사본과 실제 Excel 인쇄 PDF를 저장하고 렌더링한 페이지를 확인했다. 검증 전후 원본 해시는 동일했다.

- 제공 예시의 기본 인쇄 설정 때문에 금액·계좌 등 오른쪽 열이 두 번째 장에 분리되는 문제를 확인했다. 앱에 포함한 4개 예시 양식의 인쇄 범위·용지 방향·한 페이지 너비 설정만 보완했다. 실제 사용자가 첨부한 양식의 인쇄 설정은 기존 보존 규칙을 따른다.
- 인쇄 범위는 실제 셀과 병합 끝까지 계산한다. 오래된 `dimension` 정보 밖의 합계·각주도 포함하므로 세 줄 양식의 19행 합계와 21행 안내가 인쇄에서 빠지지 않는다. 재생성 절차는 `scripts/prepare-excel-example-print.cjs`다.
- 수정한 4개 양식, 변환 결과 3개, 실제 AI가 만든 위임장·세 줄 결과 2개에서 가로 분리 없이 각각 A4 한 페이지로 출력되는 것을 확인했다. 병합 노임명세서의 금액·계좌·서명, 위임장의 공수·청구금액이 같은 장에 표시된다.
- 표시 형식 전용 가상 파일의 Excel 셀 표시값이 `2024.01.01`, `12.50%`, `1,234,567원`, `000123`으로 앱의 기대값과 일치했다. 검증용 금액 칸은 값을 읽을 수 있는 너비로 준비했다.
- 이전 직접 수정 결과의 수식 5개를 Excel이 다시 계산한 사본과 엔진에서 대조했다. 계산값 차이 0개, 미지원 수식 0개다. 비교 테스트의 특정 비공개 파일 전용 개수 고정을 제거해 다른 Excel 정답 사본에도 적용할 수 있게 했다.

최종 검사: `EXCEL_FORMULA_GOLDEN`에 `outputs/excel-converter/live-validation/manual-recalculated-excel.xlsx`를 지정한 전체 변환기 검사 159개 통과, 조건부 사용자 파일 검사 1개 미실행. 전체 타입 검사, 변환기 범위 린트, 최종 production build가 통과했다. 빌드 시작·종료 시 코드 일치 검사와 `build/release.json` 생성도 확인했다.

4개 예시 양식을 저장소 원본과 ZIP/XML 단위로 대조했다. 인쇄 설정이 있는 통합문서·시트 XML만 변경됐으며 셀 데이터·수식·스타일·병합은 유지됐다. 근거는 `template-preservation.json`이다. 검증용 대화는 정리하고 빈 작업 화면으로 돌려두었다.

근거는 `outputs/excel-converter/live-validation/`의 `live-ai-followups.json`, `live-ai-complete.json`, `native-excel-before.json`, `native-excel-report.json`, `print-pages-fixed.json`, `live-desktop.png`, Excel 인쇄 PDF·페이지 PNG, 다운로드 XLSX·ZIP, `build.log`다. 초기 실패와 수정 후 결과를 함께 남겼다.

## 남은 한계

- 실제 Gemini로 대표 3종 양식과 연속 수정을 확인했지만, 임의의 모든 업무 양식이나 표현을 보장하는 평가는 아니다. 대용량과 더 다양한 양식의 반복 평가는 별도 범위다.
- 후속 구현에서 Gemini 기반 자유로운 서식·수식·기존 VBA 모듈 편집을 추가했다. 현재 범위는 [수식·VBA 편집](excel-converter-code-editing.md)을 따른다.
- 여러 사람에게 공통인 제목·회사명·현장명 칸은 전체 요청으로 수정한다. 그룹 합산으로 직접 수정의 대응이 모호해지면 적용을 중단한다.
- 원본 값이 여러 곳에서 반복되거나 가공된 값이면 정확한 셀 대신 원본 행 위치를 보여줄 수 있다.
- 미리보기는 서명 이미지·도형·인쇄 배치를 재현하지 않는다. 파일 내 관련 요소는 기존 보존 검사를 유지한다. 대표 예시의 실제 Microsoft Excel 계산·인쇄 PDF는 검증했으며, 물리 프린터 출력과 임의의 사용자 양식은 확인하지 않았다.
- 보관은 해당 기기의 브라우저에 한정되며 브라우저 데이터 삭제 시 사라진다. 만료 정리는 보관함을 조회할 때 수행한다.
- Hosting 배포와 Git push는 수행하지 않았다. 후속 사용자 승인으로 `functions:geminiGateway` 한 개를 배포했다.
