# 문서 양식 변환 — 간편 화면과 검증 안내

## 2026-09-16 업데이트: Gemini 3.8 Flash와 문서 미리보기

- 양식 변환 전용 `excelConversionModel=gemini-3.8-flash`, `excelConversionThinking=medium`을 실제 서버 설정에 저장하고 다시 읽어 확인했다. 기존 키와 다른 기능의 설정은 유지했다. 기록은 `outputs/excel-converter/business/AI설정_적용결과.json`에 있다.
- 모델명은 [Google 공식 모델 안내](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash)에서 확인했다. [공식 이전 안내](https://ai.google.dev/gemini-api/docs/latest-model)에 따라 Gemini 3 요청의 temperature를 제거하고 thinkingLevel을 사용한다. 2.5를 선택할 경우 기존 요청 형식을 유지한다.
- AI 설정 화면에 **위임장·노임명세서 변환 AI**를 추가했다. 모델 선택, 빠르게/균형/꼼꼼하게 분석, 권장값 채우기를 제공한다. 현재 변환 화면에도 실제 모델과 분석 강도를 표시한다. 기존 문서 OCR 설정에서 변환 설정을 분리했다.
- 실제 3.8 Flash로 위임장과 노임명세서 규칙을 받아 독립 정답과 대조했다. 첫 실측은 각각 7.5초/8.1초였으며 응답에 미해결 질문은 없었다. 이 값은 보장 속도가 아닌 해당 실행 기록이다.
- **원본 / 받을 양식 / 완성 결과** 미리보기, 개인별 문서와 시트 선택, 60~150% 배율, 크게 보기와 Escape 닫기를 추가했다. 완성 미리보기는 다운로드 버튼 위에 자동으로 표시한다.
- 병합, 글자색, 배경색, 글자 크기, 열 너비, 행 높이를 읽어 표시한다. 숨김 행/열을 제외하고 60행씩 나눠 큰 자료를 본다. 페이지를 가로지르는 병합도 원래 값을 유지한다. 서명 이미지·도형·Excel 인쇄의 완전한 재현은 제공하지 않는다.
- 자동 검증: 프런트엔드 40개 + 서버 9개. 새 모델의 실제 응답도 회귀 자료에 반영했다. 브라우저에서 새 모델로 내려받은 위임장·노임명세서 **88개 셀을 대조해 불일치 0개**를 확인했다. 확대·배율·개인별 전환, 390px 가로 넘침 없음, 새로고침 후 미리보기 복원, 오류 로그 0개도 확인했다.
- 서버 설정 값 저장과 별개로 **운영 웹/Functions 코드 배포는 실행하지 않았다**. 운영 반영 시 `getServerAiSettingsStatus`, `saveServerAiSettings`, `getExcelConversionStatus`, `planExcelConversion`의 변경도 배포해야 한다.

## 간편하게 사용하기

기본 화면을 **원본 선택 → 받을 회사 양식 선택 → AI로 변환하기 → 다운로드**로 바꿨다. 행 번호와 항목 연결은 자동으로 준비하며 필요할 때만 상세 설정을 펼친다. 추가 요청은 선택사항이다. 예를 들어 `대상월을 2026-10으로 작성해 주세요.`라고 입력할 수 있다. 여러 양식·보조자료·직접 셀 수정이 필요한 경우 상단 **상세 화면**에서 기존 기능을 사용한다.

**위임장 예시**, **노임명세서 예시**를 누르면 원본과 타회사 양식을 함께 준비한다. 예시 결과만 보려면 **AI 호출 없이 예시 결과 먼저 확인**을 사용할 수 있다. 추가 요청을 입력한 경우에는 AI 분석으로 적용한다. 완료된 작업은 현재 계정의 브라우저에 30일간 보관하며 **최근 작업**에서 다시 연다.

### 현재 사용 양식 반영

- 위임장: `src/pages/payroll/DelegationLetterPage.tsx`의 수임인·은행·계좌·현장·대상월·위임인 목록 구조를 XLSX로 재현했다. 기존 화면은 HTML 인쇄 방식이다.
- 노임명세서: `src/utils/excel/SupportPaymentExcelGenerator.ts`의 실제 생성 구조를 반영했다. 한 사람 두 줄의 주민번호/연락처, 1~16일/17~31일, 청구단가/공급가액, 은행/예금주/계좌를 함께 읽는다. 실제 기존 생성 함수의 출력도 자동 테스트했다.
- 실제 직원 자료나 서명은 가져오지 않았다. 샘플은 현재 코드의 항목·배치를 재현한 가상 자료이며, 클라우드에 저장된 사용자별 v5 양식 자체를 가져온 것은 아니다.

### 이전 Gemini 2.5 검증 기록

기존 서버 설정의 **gemini-2.5-flash**를 실제 호출하여 두 문서의 규칙을 받았고, 생성한 엑셀을 독립 정답과 대조했다. 첫 성공 기록은 위임장 입력 2,570/출력 2,140토큰, 노임명세서 입력 2,754/출력 1,922토큰이다. 개인정보 없는 응답을 회귀 자료로 저장하고 자동 테스트에서 다시 검증한다.

실제 호출에서 발견한 스키마 복잡도 HTTP 400 오류를 해결했다. 생성용 스키마만 간소화하고 서버의 범위·길이·실행 속성 검증은 유지한다. 브라우저에서 발견한 불필요한 질문과 입력 범위 확대도 보완했다. 대상에 있는 항목만 작성하고 기존 입력 범위·금액 수식을 유지하며, 지시 없는 연결 변경·제외·합산을 차단한다.

브라우저에서도 실제 API로 변환·다운로드와 추가 요청을 확인했다. 다운로드 파일은 별도 라이브러리(openpyxl)로 정답과 **127개 셀을 대조하여 불일치 0개**를 확인했다. 위임장 39개, 노임명세서 49개, 대상월 변경 위임장 39개다. 새로고침 후 이력·프롬프트 복원, 390px/1440px 가로 넘침 없음, 브라우저 오류 로그 0개도 확인했다. 수치는 `outputs/excel-converter/business/브라우저_검증결과.json`에 기록했다.

## 시작하기

- 앱 경로: `/tools/excel-converter` (로그인 필요).
- 기본 관리자 메뉴와 메뉴 경로 목록에 **엑셀 양식 변환**을 등록했다.
- 기존에 별도로 저장한 메뉴 구성을 사용하는 계정은 메뉴 관리에서 이 경로를 추가한다. 운영 메뉴 데이터는 변경하지 않았다.
- 로컬 체험: `node scripts/excel-conversion-preview.cjs --live-ai` 실행 후 `http://127.0.0.1:4189/tools/excel-converter`.
- 로컬 체험 화면은 실제 간편 화면·변환 엔진·서버 분석 함수를 사용한다. `--live-ai`에서 기존 Google 기본 자격 증명으로 서버 설정을 읽어 실제 Gemini를 호출한다. 키는 메모리에만 두며 브라우저에 보내지 않는다. 다른 PC에는 해당 자격 증명 구성이 필요하다.
- 루프백 주소, Host/Origin 검사, JSON·요청 크기 제한, 동시 1건·분당 4회 제한을 적용했다. 운영 작업 기록은 쓰지 않는다. `--live-ai`를 빼면 외부 AI 호출을 끄고 명시적인 예시 변환만 가능하다. 가짜 응답으로 AI 성공을 표시하지 않는다.

## 상세 화면의 사용 순서

1. **우리 회사 원본**에 데이터 파일을 올리고 원본 시트와 제목 행을 확인한다.
2. **상대 회사 양식**에 받을 회사의 빈 양식을 올린다. 여러 양식을 동시에 추가할 수 있다.
3. **항목 자동 연결**로 대상 열과 원본 항목을 연결한다. 바뀐 제목 행과 입력 범위도 수정할 수 있다.
4. 작성 지시를 입력하고 **Gemini로 지시 분석**을 누른다. 제안을 확인한 후 **이 규칙 적용**을 누른다.
5. AI 없이 작업하려면 **항목 연결**과 **빠른 설정으로 직접 지정**에서 동일한 규칙을 설정한다. 작성 지시가 있으면 설정에 반영했다는 확인도 필요하다.
6. **현재 양식 변환** 또는 **전체 양식 변환**을 실행한다.
7. **변환 결과**의 셀을 누르면 원본 파일·시트·행과 처리 규칙을 확인한다. 수정한 값은 재변환해야 다운로드할 수 있다.
8. **검증 결과**에서 오류와 제외 내역을 확인한다. 검증을 통과한 결과를 XLSX 또는 ZIP으로 내려받는다.

## 파일 처리 방식

Gemini는 항목 연결과 규칙을 JSON으로 제안한다. 서버와 브라우저가 허용된 규칙을 검증하며, 모델이 만든 임의 코드나 수식을 실행하지 않는다.

실제 값 계산과 엑셀 작성은 브라우저에서 수행한다. 업로드한 대상 파일의 OOXML 내부에서 입력 셀과 필요한 서식·계산 정보를 수정한다. 변경하지 않는 구성 요소는 유지한다. 기존 수식 칸은 데이터로 덮어쓰지 않는다.

생성 후 파일을 다시 읽어 입력값을 대조한다. 단순 산술과 SUM/PRODUCT/ROUND/MIN/MAX 수식은 지원 범위에서 계산한다. 지원하지 않는 수식은 오래된 계산값을 제거하고 Excel 재계산이 필요하다고 표시한다. 수식의 계산 검증이 필요한 항목은 원본 금액과 불일치하면 다운로드를 차단한다.

## 예시 및 정답

`public/excel-converter/examples`와 `outputs/excel-converter`에 다음 파일이 있다. 모두 테스트용 가상 자료다.

1. `01_우리회사_원본.xlsx` — 주문 6행, 취소·중복 상품·앞자리 0·합계 포함.
2. `02_A사_양식.xlsx` — 제목 7행, 입력 8~10행, 공급금액·합계 수식 포함.
3. `03_A사_변경양식.xlsx` — 제목 10행, 열 순서 변경, 단위·배송지 추가.
4. `04_변경양식_정답예시.xlsx` — 독립적으로 작성한 정답 파일.
5. `05_상품코드_보조자료.xlsx` — 원본 상품코드를 상대 회사 코드에 연결하는 자료.

예시 규칙: 취소 제외 → 상품코드·납기·납품처별 수량/공급가액 합산 → 납기 정렬 → 주소 결합.

기대 결과: 원본 데이터 6행 → 취소 1행 제외 → 출력 4행, 수량 **46**, 공급가액 **156,000원**. 원본 합계 행은 구조상 제외 내역에 별도 기록된다. 기존 양식은 입력 칸이 3행이므로 2개 시트로 나뉜다.

## 실제 Gemini 사용과 운영 확인

- 운영 앱은 `planExcelConversion` Firebase Callable을 호출한다. `asia-northeast3` 리전이며 로그인과 사용자 승인 상태를 확인한다.
- `/settings/ai`의 기존 서버 설정을 사용한다. 브라우저에 API 키를 넣지 않는다.
- 서버로 보내는 내용은 원본 항목명·형식, 대상 양식 설명·수식, 사용자가 입력한 작성 지시·고정값·규칙이다. 원본 데이터 행과 직접 수정한 행 값·원본 행 추적은 전송에서 제외한다.
- 같은 요청 재시도는 작업 ID를 재사용한다. 서버는 완료 응답 재사용과 사용자별 분당 4회 제한을 적용한다.
- 서버 작업 기록에는 분석 결과와 사용량이 저장된다. `expiresAt`는 7일 뒤로 지정한다. 실제 자동 삭제에는 해당 작업 컬렉션의 Firestore TTL 설정이 필요하다.
- 2026-09-16 서버 반영 완료: `planExcelConversion`, `getExcelConversionStatus` 생성 및 `getServerAiSettingsStatus`, `saveServerAiSettings` 업데이트. 실제 `localhost:3000` 앱의 로그인 세션에서 배포된 상태 확인 함수가 `Gemini 3.8 Flash · 균형 분석`을 반환함을 확인했다. 웹 Hosting은 이번 수정에서 배포하지 않았다. TTL 동작은 미검증이다.

### 실제 앱의 `internal` 오류 수정 (2026-09-16)

- 원인: 로컬 검증 화면은 Gemini 연결 도우미를 사용했지만 실제 앱이 호출하는 두 Firebase Callable이 서버에 없었다. 배포 함수 목록과 실제 앱의 오류 화면에서 확인했다.
- 수정: 위 네 서버 함수를 해당 프로젝트의 `asia-northeast3`에만 반영했다. 클라이언트는 `internal`·연결 실패·로그인 만료·사용량 제한·시간 초과를 한국어 안내로 바꾼다. 연결 재확인 실패 시 이전 성공 상태를 제거한다.
- 서버 설정·저장소 예외를 안전한 오류로 변환하고, 실패 기록 저장 오류가 최초 오류를 덮지 않도록 했다. 응답 본문을 읽는 동안에도 AI 제한 시간이 적용된다. 로그에는 실패 단계만 남긴다.
- 이번 검증: 클라이언트·변환·미리보기 테스트 42개, 서버 테스트 11개 통과. 전체 TypeScript 검사, 수정 파일 lint, Functions 빌드, 웹 운영 빌드, 변경 공백 검사 통과. 실제 앱의 배포 서버 상태 확인 성공.
- 현재 한계: 실제 앱에서 가상 예시를 Gemini로 변환하고 다운로드하는 검증은 자동 승인 검토가 외부 전송 및 파일 열람으로 차단하여 사용자 승인 대기 중이다. 앞선 로컬 연결 도우미 검증을 배포된 Callable 전체 흐름 검증으로 간주하지 않는다.
- 배포 준비 시 함수 탐색의 기본 10초 제한에 걸려 `FUNCTIONS_DISCOVERY_TIMEOUT=60`으로 재시도했다. [Firebase 공식 안내](https://firebase.google.com/docs/functions/tips#avoid_deployment_timeouts_during_initialization)를 따른다.

## 병합 셀·매크로 통합문서 개선 (2026-09-16)

- 입력 영역에 세로 병합이 있다는 이유만으로 중단하던 제한을 제거했다. 머리글 아래에서 병합 전체를 한 사람의 입력칸으로 취급하고 시작 셀에만 작성한다. 병합·행 높이·열 너비는 그대로 유지한다.
- 표의 물리적 행 수 대신 입력칸 수로 수용 인원·초과 페이지·원본 금액 대조 위치를 계산한다. 병합된 두 줄 머리글도 인식한다. 반복 입력과 관계없는 문서 제목의 세로 병합은 개인별 서식 작성을 막지 않는다.
- `.xlsm` 원본과 대상 업로드를 지원한다. 받을 양식의 실제 파일 형식으로 저장하고 VBA·ActiveX·버튼 관련 ZIP 구성요소는 실행하거나 읽어들이지 않고 원본 바이트로 보존한다. 매크로 양식은 시트를 복제하는 대신 통합문서 파일별로 분리해 시트 코드명과 참조를 유지한다. 원본 파일의 매크로를 다른 회사의 `.xlsx` 양식으로 복사하지 않는다.
- 간편 화면에 **병합 셀 예시**를 추가했다. 가상 노임명세서에서 3명·7공수·1,270,000원을 두 줄씩 병합한 타회사 양식으로 옮긴다.
- 검증: 관련 52개 테스트 통과. 브라우저에서 예시 변환·미리보기·`.xlsx` 다운로드 후 별도 라이브러리로 24개 셀 대조(불일치 0), 병합 32개·수식 유지 확인. 매크로 없는 정상 `.xlsm` 업로드·변환·다운로드 후 다시 읽기 성공. VBA·버튼 바이너리 보존은 자동 테스트의 불투명 바이트 표식으로 검증했으며 실행 가능한 실제 VBA의 Excel 동작을 검증한 것은 아니다.
- 이번 브라우저 검증은 외부 AI 전송 없이 실제 변환 엔진으로 수행했다. 서버 API는 이번 변경 대상이 아니다. 실제 회사 파일은 아직 제공되지 않아 동일 파일 재현 검증은 남아 있다.

## 지원 범위와 남은 한계

- `.xlsx`와 `.xlsm`을 지원한다. 구형 `.xls`, 바이너리 `.xlsb`는 Excel에서 지원 형식으로 저장해야 한다. 파일당 20MB, 압축 해제 합산 100MB, 시트당 30,000행·100열·사용 셀 250,000개, 파일당 30개 시트로 제한한다. 간편 화면은 원본·대상 각 1개, 상세 화면은 각각 최대 10개다.
- 현재 두 줄 노임명세서 읽기, 개인별 고정 입력칸, 각 항목의 인원 구간이 일치하는 세로 병합 입력칸을 지원한다. 한 사람의 아래 행에 서로 다른 항목·수식이 있거나 항목별 병합 구간이 다르면 자동으로 덮거나 누락시키지 않고 확인을 요청한다. 하단을 밀어내는 행 확장과 여러 단계 피벗 재구성은 지원하지 않는다. 개인별 월 급여명세서의 모든 변형이나 클라우드 v5 사용자별 양식까지 검증한 것은 아니다.
- 암호화·외부 연결·문서 전자서명 파일과 보호된 대상 시트는 처리하지 않는다. 매크로와 포함된 실행 개체는 실행하지 않는다. Excel 표·메모·피벗이 포함된 양식의 시트 복제는 중단한다.
- 사용자 지정 검증 수식, 고급 Excel 수식, 매크로, 피벗 갱신은 별도 Excel 확인이 필요하다. Excel 데스크톱의 실제 인쇄·재계산은 이번 환경에서 확인하지 않았다.
- 웹 미리보기는 셀 값 확인용이다. Excel과 동일한 인쇄 화면이나 모든 도형의 시각적 재현을 제공하지 않는다.
- 파일·양식·규칙·이력은 현재 브라우저에 보관한다. 팀 공유, 다른 기기 동기화, 중앙 승인·서버 일괄 작업 큐는 이번 구현에 포함하지 않았다. 브라우저 데이터를 지우면 저장된 파일도 사라진다.
- 실제 회사 양식은 제공되지 않았으므로 가상 예시로 검증했다. 실제 양식의 복잡한 병합·수식·인쇄 요구사항은 샘플을 받아 추가 검증해야 한다.
