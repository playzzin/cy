# 팀 메뉴 결함 수정 기록

첨부된 15개 항목을 현재 작업 폴더의 코드와 대조해 수정했다. 작업 시작 전에 존재하던 다른 변경사항은 유지했다. 운영 배포나 운영 DB·Storage 자료 변경은 실행하지 않았다.

| 번호 | 문제 | 반영한 변경 |
| --- | --- | --- |
| 1 | 임시자료 동시 정리가 재사용한 신청까지 삭제 | 부모 신청에 `discarded` 기록을 영구 유지하고 첨부 하위 자료만 정리. 업로드에서 정리 중/완료 ID 재사용 거부 |
| 2 | 권한 축소 후 옛 토큰으로 DB 접근 | Firestore 역할 판단을 현재 사용자 문서로 제한 |
| 3 | 서명 Storage 경로의 로그인 사용자 전체 접근 | 공통 허용 경로에서 서명 제외. 새 작업자별 경로는 현재 활성 계정의 본인 연결 또는 사무실·급여·관리 권한 검사. 기존 평면 경로는 사무실·급여·관리 권한으로 제한 |
| 4 | 팀·회사·현장 목록 공용 캐시 | 계정 간 재사용될 수 있는 서비스 목록 캐시 제거. 팀 서버 조회의 계정별 진행 중 요청 병합은 유지 |
| 5 | 퇴사·비활성 작업자가 권한 근거로 잔류 | 팀 조회에서 퇴사·비활성 연결 작업자를 제외 |
| 6 | 승인 권한 검사와 저장 사이 권한 변경 | 신규자·경비 승인 거래 안에서 사용자와 동적 직책 설정을 다시 읽고 승인 권한 검사 |
| 7 | 영수증 공개 다운로드 링크 | 새 영수증에 다운로드 토큰 발급 중단. 신청·경비 관리·경비 상세 화면 모두 권한 검사 서버를 거쳐 파일 열람 |
| 8 | 일반 팀장 가불 신청·취소 실패 | 본인 작업자 연결을 검사하는 `teamAdvanceRequests` 서버 기능으로 신청·취소 이동 |
| 9 | 가불 중복·한도 초과 동시 신청 | 서버가 근무·지급·활성 신청 금액 재계산. 작업자 단위 거래 직렬화. 재시도 요청 ID와 내용 지문으로 중복 저장 및 ID의 다른 용도 재사용 차단 |
| 10 | 정산 저장 중 새 메모 유실 | 저장 시작 후 문서가 편집됐으면 최신 문서를 유지하고 저장된 스냅샷만 기준값으로 기록. 팀·월 변경 시 이전 저장 결과 적용 차단 |
| 11 | 이전 월 지원 금액이 현재 월을 덮음 | 경비 조회 세대 구분, 이전 응답 무시, 새 조회 시 이전 금액 비우기, 조회 중 CSV 비활성화 |
| 12 | 가불 저장 중 월 변경 후 계산 중 고정 | 저장·취소 완료 후 항상 현재 화면의 조회 함수를 호출 |
| 13 | 동적 직책·내부 매니저 분류 불일치 | 사용자 직책 ID를 메뉴 설정의 실제 이름으로 해석. 내부 매니저의 전체 조회 경로 보존 |
| 14 | 권한 축소 뒤 타인 신청 화면 잔류 | 추가 페이지 병합 시 현재 권한으로 이전 행 재필터링, 열려 있는 승인 대상 제거 |
| 15 | 내부 메뉴 이동 시 미저장 입력 유실 | 신규자·경비 입력 화면에 BrowserRouter 이동 확인 추가. 취소하면 입력 유지 |

## 최초 수정 검증

- 프런트 TypeScript 검사 통과.
- Functions 빌드 통과.
- 프런트 프로덕션 빌드 통과(`Compiled successfully`, exit 0).
- 수정한 프런트 파일 ESLint 통과.
- 화면·서비스·회귀 테스트 9개 묶음, 59개 통과.
- 로컬 Firebase Auth/Firestore/Storage 에뮬레이터에서 가불 동시 신청·재시도·취소, 동시 임시자료 정리, 퇴사 연결 차단, 신규자 승인, 옛 토큰의 권한 회수, 다른 작업자 및 비활성 계정의 서명 업로드 차단 및 영수증 승인·열람 시험 18개 통과. 두 에뮬레이터 실행과 전체 실행기가 모두 exit 0으로 종료.
- 운영 계정으로 실제 브라우저 업무를 수행하거나 실제 지급·승인·다운로드를 실행하지 않았다. 화면 상호작용 검증은 React DOM 테스트 환경에서 수행했다.

## 최초 수정 당시 후속 작업

1. 새 `teamAdvanceRequests`와 수정한 `teamExpenseRequests`, `teamWorkerRequests`, `getTeamScopedData` 서버 기능, Firestore/Storage 규칙, 프런트를 함께 배포해야 한다. 프런트만 먼저 배포하면 새 서버 기능을 호출할 수 없다.
2. 이미 발급한 영수증 및 서명 다운로드 토큰은 규칙 변경으로 회수되지 않는다. 기존 공개 링크의 완전한 회수는 해당 Storage 객체의 토큰을 제거하는 별도 운영 작업이 필요하다. 이번 작업에서는 기존 파일의 토큰을 변경하지 않았다.
3. 기존 서명 평면 경로에 대한 작업자 직접 Storage 접근은 제한된다. 기존 다운로드 URL 회수와 함께 작업자별 경로 및 권한 확인 방식으로 이전할 범위를 운영 검토해야 한다.
4. 내부 메뉴의 이동 확인을 구현했다. 브라우저 자체 뒤로/앞으로 이동의 차단은 이 변경의 검증 범위에 포함하지 않는다.

에뮬레이터 시험 실행: `npm run functions:build` 후 `node scripts/run-team-request-tests.cjs`. 합성 자료만 쓰는 `demo-team-*` 프로젝트를 사용한다.

### 서명·영수증 공개 링크 회수

- 기존 서명은 권한 확인 서버를 통해 읽도록 표시 화면 11개를 보완했다. 신규 서명은 공개 토큰 없는 작업자별 파일로 저장하고, 브라우저의 직접 서명 업로드는 차단한다.
- 기존 서명 133개의 공개 다운로드 토큰을 모두 제거했다. 기존 링크 133개가 차단되며, 파일 세대·해시·크기 비교에서 원본 133개가 모두 변경되지 않았음을 확인했다.
- 서명을 참조하는 작업자 111건의 연결 경로를 검사했으며, 해석할 수 없거나 다른 작업자를 가리키는 경로는 0건이었다. 작업자 문서는 변경하지 않았다.
- 기존 `team-expense-receipts/` 객체는 0건이었다. 신규 영수증은 공개 토큰 없이 생성된다.
- 원본 삭제·재업로드 없이 토큰 메타데이터만 변경했다. 운영 스크립트는 `scripts/secure-team-private-files.cjs`이며 기본 모드는 읽기 전용이다.

### 검증 한계

- 실제 운영 급여 지급·승인·신청·서명 저장은 실행하지 않았다. 관련 쓰기와 동시 처리·권한 회수는 합성 자료를 사용하는 에뮬레이터 시험으로 검증했다.
- 브라우저 자체 뒤로/앞으로 이동 차단과 실제 인쇄·문서 내보내기는 이번 운영 확인 범위에 포함하지 않았다.
- Firebase 규칙 컴파일에 사용하지 않는 기존 보조 함수·변수 관련 경고가 남지만, 두 규칙 파일 모두 컴파일·배포 및 실제 내용 대조를 통과했다.
