## 남은 작업 추가 검수 결과

실제 전체 앱과 로컬 Firebase를 연결하여 미승인 로그인 → 팀장 승인 → 새 브라우저 재로그인 → 가불 신청 → 사무실 승인·지급완료 상태 → 팀장 재조회와 정산 월 이동을 확인했다. 실제 계정이나 송금을 사용하지 않았다.

312개 라우트 항목을 390/1366px에서 진입·캡처한 최종 624개 조건에서 감지된 런타임 예외·문서 전체 가로 넘침·보이는 조작 요소의 잘림은 0건이다. 원본에 회사 DB 경로가 중복 선언되어 고유 경로는 311개이며 목록과 캡처에 두 항목을 보존했다. 표 내부의 의도된 가로 스크롤은 유지한다. 수정과 관련된 39종 화면을 캡처로 추가 검토했으며 모든 화면의 모든 데이터·권한·기능 상태를 검증한 것은 아니다.

증거는 `artifacts/client-workflow-qa/`에 저장했다. Android·카카오톡 실제 수신은 사용자가 현재 휴대전화를 연결할 수 없어 미검증으로 남긴다. [실기기 절차](./android-kakao-photo-qa.md)와 합성 PNG를 준비했다.

이번에 수정한 문제:

- 일반 팀원 승인 시 직책 문서에 중복 `id` 필드가 없으면 빈 값 비교로 거절되던 문제를 수정했다. 비어 있지 않은 문서 ID·직책 ID·직책 이름만 비교한다. 일반 역할 이름을 가진 관리자 권한은 계속 거절하는 회귀 검사도 추가했다.
- 가불 신청·취소 직후 재조회가 성공 안내를 지우던 문제를 수정하고 두 동작을 테스트했다.
- 정산 고정 바의 반투명 배경에 본문 글자가 겹치던 문제를 수정했다.
- 현장·작업자·팀·회사 표의 AG Grid 모듈을 각 화면에서 독립적으로 초기화했다. 새 브라우저에서 2/4/2/1개 합성 행 표시를 모바일·PC 모두 확인했다.
- 모바일 위임장 도구가 캔버스 높이를 밀어내던 배치를 세로 패널과 560px 편집 영역으로 바꿨다. 390px 화면에서 텍스트 위젯을 실제 추가했다.
- 일보·지원·견적·DB·업로드·메시지 등의 툴바·검색·표 폭을 정리했다. 숨은 Excel 도움말과 긴 AI 설정 식별자의 문서 넘침을 수정했다. 금액 계산식과 출력 규격은 유지했다.

실행기: [로컬 검수 안내](../scripts/client-workflow-qa/README.md). 실제 React 앱·Firebase SDK·Auth/Firestore/Storage 에뮬레이터·현재 Rules를 사용한다. callable은 로컬 HTTP 어댑터에서 실제 컴파일된 서버 handler를 실행하고 로그인 토큰을 검증했다. 배포된 Functions·Functions 이벤트 트리거·외부 API는 이 결과에 포함하지 않는다.

624개 조건 중 자동 분류는 `rendered` 580개, 안내 문구 검토 표시 `unavailable` 42개, 상세 fixture 부족 표시 2개다. 안내 분류에는 정상 설명도 포함되므로 실패 42건이라는 뜻이 아니다. 상세 문서 없는 경로는 빈 상태만 검사했다. 팀장 전용 승인 화면은 별도 팀장 흐름에서 통과했다. 계획서·카드 상세·AI 등 검수 어댑터에 없는 서비스, 복지 자산의 합성 계정 권한 제한은 연동 통과로 계산하지 않는다. 경로별 경계와 캡처는 [전체 목록](./client-mobile-route-design-inventory.md)에 기록했다.

## 승인 범위와 출시 순서

`teamAccountApprovals`는 현재 user 문서의 팀장 직책과 연결된 작업자 문서의 팀장 직책을 모두 확인한다. 실제 worker.uid 연결이 필요하다. 일반 작업자 역할만 처리하며 관리자·사무실·회사·미등록·타팀·본인·정지·퇴사와 추가 특수 권한은 거절한다. 승인 자체는 Firestore 트랜잭션으로 처리하며 중복 승인 시 이미 활성화된 연결을 재사용한다. claims 갱신 실패는 승인 완료와 구분하고 같은 행에서 재시도한다.

1. 서버 Functions·기존 Rules의 검수된 버전을 먼저 배포하고 합성 계정으로 확인한다.
2. 이후 프런트 빌드에서 `REACT_APP_TEAM_ACCOUNT_APPROVALS_ENABLED=true`로 승인 진입점을 활성화한다. 기본값은 비활성이다.
3. 저장된 운영 메뉴는 이번 작업에서 변경하지 않는다. 프런트의 `ensureTeamPersonnelMenu`가 팀장 메뉴만 메모리에서 정리한다. 사무실·관리자 설정은 보존한다.
4. 복구 시 승인 진입점만 비활성화하고 서버 권한 검증·직접 쓰기 차단은 유지한다. 기존 승인 계정을 일괄 취소하지 않는다.

## 남은 검수와 운영 상태

- 실제 휴대전화의 카카오톡 수신과 키보드·큰 글꼴은 사용자가 현재 연결할 수 없어 남겼다. 합성 계정 재로그인·사무실 지급 상태는 로컬 전체 앱에서 통과했으며 운영 E2E는 미검증이다.
- R18은 312개 경로의 적용·유지 결정, 624개 진입·캡처 조건, 39종 화면의 추가 캡처 검토까지 수행했다. 실제 문서·외부 서비스·모든 권한 상태의 전체 기능 검수와 구분한다.
- 새 계정 승인 기능은 기본 비활성이다. 서버·Rules 검증 및 배포 후 프런트 진입점을 활성화한다.

## 검수 중 발견해 수정한 문제

- 모바일 정산 바의 기존 `min-width: 0` 규칙이 월 버튼을 압축했다. 월 조작은 별도 행으로 배치해 연월과 양쪽 버튼을 모두 보이게 했다.
- 2열 현장 카드에서 참여 팀 수가 가려졌다. 숫자와 참여 팀 요약을 세로로 배치했다.
- 기존 신규 작업자 등록의 동시 승인 테스트에서 `Transaction is invalid or closed`가 반복됐다. 같은 트랜잭션의 문서 읽기를 `getAll`로 묶고 이름 중복 쿼리는 뒤에 실행하여 회귀 검증을 통과했다. 기존 중복 잠금과 사무실 승인 정책은 유지한다.
- 첫 전체 검사에서 빌드와 동시 실행하던 기존 숙소 화면 테스트가 시간 초과됐다. 빌드와 테스트를 순차 실행한 최종 검사에서는 통과했다.
- 기존 차량 정비 이동 보호 테스트가 관계없는 청구 마감 컴포넌트를 통해 Firebase를 초기화하면서 실행 전에 실패했다. 해당 컴포넌트만 테스트 대역으로 분리했다. 탭·월 이동 보호 검증은 유지하며 개별 2건과 최종 전체 검사 모두 통과했다.

## 로컬 고객 검수 순서

1. 팀장 진입 → 현황판 2열과 전체 현장명 → 카드 상세 펼침.
2. 작업자정보 → 전체/재직/퇴사 → 조회월 → 근무내역 → 달력 날짜 상세 → 목록.
3. 신분증 사진 미리보기 → 파일 공유 또는 저장/복사. 외부 전송은 지정된 합성 테스트 자료로 별도 검수.
4. 가불 신청 → 허용 작업자·금액·기존 계좌 확인 → 신청 → 사무실 접수 상태 확인.
5. 정산 하단 스크롤 → 고정 월 조작 → 변경사항이 있으면 기존 폐기 확인.
6. 승인 기능 활성화 후 자기 팀 계정만 선택 → 대상 확인 → 승인 → 일부 실패와 권한 갱신 결과 확인.
7. 역할·소속 변경 → 열린 화면 재구성, 옛 입력 URL 차단, 사무실 입력 유지 확인.

이전 `client-mobile-workflow` 브라우저는 실제 UI 컴포넌트와 fixture 서비스를 사용하며 정산은 합성 본문이다. 추가 `client-workflow-qa`는 실제 전체 앱과 로컬 Firebase를 연결했다. 두 검사를 구분하며 어느 결과도 운영 E2E 또는 Android·카카오톡 수신 통과로 표현하지 않는다.
