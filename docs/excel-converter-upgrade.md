# Gemini 엑셀 양식 변환

## 처리 흐름

1. 원본·대상 파일을 브라우저에서 읽는다. 모든 시트의 전체 행, 열, 병합, 숨김 상태를 반복 패턴으로 압축한다.
2. 개인정보 값 대신 알려진 항목명과 값의 종류를 보낸다. 선택한 두 시트의 가린 미리보기도 보조 입력으로 사용한다. 그림은 최대 24행·60열이며 전체 구조는 별도 자료에 포함된다.
3. Gemini가 원본의 인원 구간, 한 사람당 줄 수, 각 항목의 줄 위치와 대상 입력 구간을 결정한다. 확인된 전용 원본 읽기는 계좌 분리 등의 동작을 보존한다.
4. Gemini가 자연어 요청을 제한된 작성 규칙으로 만든다. 임의 코드 실행은 지원하지 않는다.
5. 브라우저가 실제 값을 원본 양식 ZIP에 작성하고, 저장된 값을 다시 읽어 대조한다. 인원, 날짜별 값, 기존 수식 대조 항목, 병합, 행 높이, 열 너비, 인쇄 설정, 그림·매크로 부품을 검사한다.
6. 오류가 있으면 최대 두 번 규칙을 보정한다. 해결되지 않은 오류가 있는 결과는 다운로드에 제공하지 않는다. 모호한 구조는 대화로 확인한다.
7. 성공한 구조와 연결 규칙만 계정별 브라우저 저장소에 30일간 최대 12개 보관한다. 개인정보 행, 파일, 대화, 수동 변경값, 필터값, 고정값은 저장하지 않는다. 도움말에서 기억한 양식을 지울 수 있다.

## 예시와 검증

- 도움말의 노임명세서·위임장·새로운 세 줄 양식 버튼에서 가상 파일로 체험한다.
- `structure.test.ts`: 1,200명 전체 구조, 개인정보 가림, 세 줄 추출, 열 순서 변경, 날짜 연결 오류, 기억 재사용·만료 규칙, 저장 결과 대조.
- `ChatConversionWorkspace.test.tsx`: 실제 작성기 연결, 대화 후속 요청, 중단, 자동 보정 성공 및 실패 시 다운로드 차단.
- `laborTwoRow.test.ts`: 16/17일 원본과 15/16일 대상 연결, 공유 수식, 소수 저장 오차. 실제 파일 통합 검사는 `EXCEL_PAIR_SOURCE`, `EXCEL_PAIR_TARGET` 환경변수를 지정해 실행한다. 사용자 파일은 저장소에 넣지 않는다.
- 서버 검사는 `excelConversionPlanning.test.ts`, `excelStructurePlanning.test.ts`, `excelConversionModel.test.ts`를 빌드한 뒤 실행한다.
- 로컬 브라우저 검증은 `node scripts/excel-conversion-preview.cjs --live-ai`로 실행한다. 기존 Google 인증과 서버 AI 설정이 필요하며, 원본 파일 값은 서버에 전송하지 않는다.

## 운영상 범위

- 한 사람당 1~10줄의 일정한 반복 구조를 지원한다. 불규칙한 반복, 의미를 알 수 없는 항목, 필요한 원본 정보가 없는 요청은 확인이 필요하다.
- 매크로 파일의 원래 VBA 부품을 보존하지만 매크로를 실행하거나 작성하지 않는다.
- 지원하지 않는 복잡한 수식은 오래된 계산값을 지우고 Excel 재계산 안내를 표시한다. 이를 계산 검증 완료로 표시하지 않는다.
- 기억한 양식에도 매번 현재 요청 분석과 결과 검증을 수행한다. 구조가 바뀌면 다시 분석한다.
- 서버 배포 대상은 `analyzeExcelStructure`, `planExcelConversion`이다. 서버 배포 성공과 인증 차단 검증 후 Hosting을 배포한다.
