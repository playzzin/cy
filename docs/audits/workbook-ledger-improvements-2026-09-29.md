## 추가 안전장치와 사용성

- 수정·삭제 직전에 조회 범위 밖의 연결 내역도 다시 조회한다. 연결된 원본을 삭제하거나 다른 종류의 거래로 바꾸는 작업을 차단한다. 대량 삭제는 연결 내역부터 처리하고, 실패하면 완료 건수를 알린다.
- 정산 미리보기 이후 전체 이력 검증에 실패하면 미검증 결과를 지우고 내보내기·인쇄·정산 작업을 막는다. 화면 내 오류 안내와 다시 불러오기 버튼을 추가했다.
- 최초 입력폼 진입에서 회사·현장·팀 자동완성 목록을 즉시 반영한다.
- DB 검색이 현재 불러온 일부 데이터에 적용된다는 안내와 전체 검색 버튼을 추가했다. 기존 필터 해제 버튼은 `미매핑 필터 해제`로 이름을 명확히 했다.
- 거래장의 잔액이 조회 기간 내 차액이며 이전 기간 이월액을 포함하지 않는다는 설명을 추가했다.

## 실제 검증

- 후속 재검사에서 거래대장 테스트 78개와 카드 명세서 테스트 10개, **총 10개 파일·88개 테스트가 통과**했다. 계산, 백업 연결 복원, 입력 검증, 401건 저장의 두 번째 묶음 실패, 남은 항목 재시도, 조회 범위 밖 연결 보호, 정산 조회 실패 후 재시도를 포함한다.
- 거래대장 관련 파일과 카드 명세서 테스트를 포함한 TypeScript/TSX 11개 파일의 ESLint 통과.
- 전체 `npm run typecheck` 최종 통과. 이전에 차단 원인이었던 `src/services/cardStatementStoredReadService.test.ts`의 callable mock은 후속 작업 시작 시 이미 `stream` 속성을 포함하고 있었다. 이를 다시 수정하지 않고 현재 코드의 검사·테스트로 해결 상태를 확인했다. 결과 로그: `artifacts/workbook-ledger-followup-typecheck.log`.
- 운영용 빌드 최종 성공(`Compiled successfully`, 종료 코드 0). 이전 카드 명세서 테스트 TS2345 차단도 해소됐다. 로컬 검증 산출물: `artifacts/workbook-ledger-followup-build`, 결과 로그: `artifacts/workbook-ledger-followup-build.log`.
- 실제 Chrome의 별도 검증 탭에서 입력폼, DB, 거래장, 전체 조회, 분기 부가세 화면을 확인했다. 거래장의 잔액 설명 표시, 정산 검증 중 버튼 비활성화와 검증 완료 후 활성화, 부가세 표 렌더링을 확인했다.
- DB의 `전체 데이터에서 검색` 버튼으로 전체 조회를 완료한 뒤 일부 데이터 안내가 사라지는 것을 확인했다. 검증 후 입력폼으로 돌아와 작성 0건과 개발 오류 화면이 없는 상태를 확인했다.
- 후속 배포 요청에 따라 운영 버전을 기준으로 거래대장 변경 10개 파일을 분리한 `c4176dc8`을 Hosting에 배포했다. 배포본 전체 테스트 2,134개 통과, 운영 버전·정적 파일 일치 및 운영 화면 확인을 마쳤다. [운영 배포 기록](./workbook-ledger-deployment-2026-09-29.md).

## 남은 위험과 미검증 범위

- 서버 조회와 쓰기는 하나의 원자적 작업이 아니므로 다른 사용자의 동시 수정·삭제를 완전히 막는 서버 트랜잭션 보호는 남아 있다.
- ID가 없는 예전 백업 파일은 기존 중복 추정 기준을 사용한다. 연결 원본을 확인할 수 없는 파일은 가져오기를 중단한다. 기존 데이터를 추정으로 자동 보정하지 않았다.
- 삭제 복원 화면, 전체 페이지의 추가 분리, 모바일·인쇄·캡처 결과는 이번 수정 범위에 포함하지 않았다.
- 이전에 브라우저 확장 프로그램 창으로 중단됐던 거래장 설명·정산·부가세 화면 검증은 후속 작업에서 완료했다. 실제 네트워크 장애 주입은 하지 않았으며 조회 실패와 재시도 흐름은 자동 테스트로 검증했다.
- 실제 DB 등록·수정·삭제, 지급 처리, 운영 데이터 업로드, Git push는 수행하지 않았다. 저장 실패와 삭제 보호는 모의 저장소에서 검증했다.
