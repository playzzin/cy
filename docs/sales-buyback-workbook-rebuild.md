# 현장별 바이백 워크북 재구성 기획

> 운영 기준: 바이백의 원천 문서는 `현장 + 청구월` 기성 문서다. 영업사원·관계자는 현장 바이백의 배분/지급 대상이며, 1차 탐색 기준이 아니다.

## 1. 원본 워크북 분석 요약

원본 `영업사원 바이백~★.xlsx`는 영업사원 8명을 각각 별도 시트로 관리한다.

- 이종훈 차장님
- 나재학 부장님
- 김태섭 팀장님
- 임근록 팀장님
- 김정삼 부장님
- 현성은 차장님
- 주선식 과장님
- 윤동규 팀장님

공통 원장은 다음 열을 사용한다.

| 엑셀 열 | 의미 | 웹 데이터 |
| --- | --- | --- |
| 날짜 | 귀속월 또는 정산 대상 기간 | `yearMonth` |
| 현장 | 현장과 거래처를 합쳐 적은 표시명 | `siteId` + 현장 스냅샷 |
| 세전 | 영업사원 바이백 총액 | 배분 계산금액(총액) |
| 세후 | 실제 지급 대상액 | 정산방식별 계산 결과 |
| 세금 | 세전에서 세후를 뺀 금액 | 보류/세금 계산 결과 |
| 비고 | 차액, 보존, 계산식, 입금 예정 등 | 배분 메모 + 지급 메모 |
| 입금 | 입금 완료 여부 | 지급상태 |
| 추가 날짜 | 일부 시트의 실제 입금일 | 지급일 |

대부분의 행은 `세후 = 세전 × 75%`, `세금 = 세전 - 세후`를 사용한다. 다만 다음 예외가 실제 데이터에 존재한다.

- 계산서 처리처럼 세후가 0이고 세금 쪽에 전액이 잡히는 행
- 세후 금액을 직접 정리한 행
- 공수당 차액, 보존금, 임대료·망 판매·인건비 등 수기 산식만 있는 행
- 입금 예정일 또는 실제 입금일이 비고/추가 열에 기록된 행
- 바이백과 별도로 장기 공제·회차·잔액을 계산한 보조 표

따라서 웹에서는 75/25를 기본값으로 제공하되, `비율`, `계산서 전액`, `세후 직접입력`을 모두 지원해야 원본을 손실 없이 옮길 수 있다. 자유식 산식은 구조화된 입력값과 메모를 함께 보존한다.

### 원본 감사 수치와 이관 검토 항목

- 8개 시트의 확인 합계는 세후/바이백 `1,365,722,169.5원`, 세금·공제 `373,493,261.5원`, 두 금액을 합친 세전 기준 `1,739,215,431원`이다.
- 이종훈 시트 121행은 세전 `1,129,100원`인데 세후+세금이 `1,456,545원`으로 `327,445원` 초과한다. 자동 이관하지 않고 검토 큐에서 원본 확인 후 확정해야 한다.
- 각 시트에는 약 1,000행까지 수식이 미리 채워져 있으나 실제 거래행은 훨씬 짧다. 가져오기는 사용영역이 아니라 날짜·현장·금액·비고 중 하나라도 실데이터가 있는 행을 기준으로 종료한다.
- 음수 조정, 팀 간 이관, 100/0·0/100, 수기 세후, 보존금은 일반 지급행과 구분해 별도 조정유형과 사유를 보존해야 한다.
- 임근록 시트에는 카니발 60회 납입표(회당 861,960원, 총 51,717,600원)와 대여금 원장이 있다. 확인 당시 32회 납입, 28회/24,134,880원이 잔여로 표시된다.
- 나재학 시트에는 계좌별 용도표, 노무·세금계산서 원장, 임대료 정산 이미지가 있다.
- 이종훈 시트에는 별도 대사표, 김정삼 시트에는 실제 지급일, 윤동규 시트에는 청구 차이 보조표가 있다.
- 위 보조 원장은 단일 바이백 행으로 합치지 않는다. `buyback_payment_events`, 반복 공제/대여금, 첨부·대사 엔터티로 분리하고 원본 행과 상호 참조한다.

## 2. 현장 중심 재구성의 핵심 문제

기성관리의 바이백은 `progress_claims(siteId + yearMonth).allocations[]`에 포함되어 있다. 기존 화면은 이 현장 문서보다 영업사원별 확정 배분 행을 먼저 보여 주어 다음 문제가 생겼다.

- 작성중·검토중·미배분 현장이 대장에서 사라짐
- 한 현장의 바이백 원금이 대상자 행 수만큼 중복 집계될 위험
- 사무실 귀속액과 외부 지급액의 구분 부족
- 선택 현장과 관계없는 다른 현장 지급행이 같은 표에 섞임
- 확정 문서가 현재 출력일보로 다시 계산되어 보일 위험

정산대상자 스키마는 `salesperson`을 지원하지만 관리 화면은 관계자/기타만 편집할 수 있다. 기존 영업사원을 수정하면 관계자로 바뀔 수 있어 먼저 차단해야 한다.

기성 배분의 `targetId`는 정산대상자 ID로 쓰이지만 지원현장 배분의 `targetId`는 회사 ID나 수기 대상까지 섞여 있다. 새 연결은 이름이나 기존 다형 `targetId`가 아니라 `settlementTargetId`를 명시적으로 사용한다.

## 3. 목표 UX

`/payroll/progress-claims?tab=buyback`를 네 영역으로 구성한다.

1. 선택월 현장별 바이백 현황
   - 발주사 안의 관리 대상 현장을 `현장 + 청구월` 기준으로 1행씩 표시
   - 작성중·검토중·미배분·바이백 0원 현장도 유지
   - 공수·금회기성·팀포지션·바이백 가능액·대상자 배분·사무실 귀속·미배분·세후·실입금·미지급 표시
   - `미작성 → 산정 → 배분 → 확정 → 지급 → 완료` 상태 표시
   - 현장 행 선택 시 URL의 `siteId`, `month`, `tab=buyback` 문맥 유지
2. 선택 현장 바이백 산정
   - 금회기성, 공수, 팀포지션, 바이백 가능금액 계산
   - 배분 기준금액 적용과 메모
3. 정산대상자 배분
   - 정산대상자 ID 선택
   - 고정금액·비율·공수당·직접입력
   - 75/25, 계산서 전액, 세후 직접입력
   - 지급상태·예정일·입금일·증빙상태
   - 실입금액과 부분입금/과입금 잔액
   - 초과배분과 미연결 대상 경고
4. 선택 현장 지급·증빙 대장
   - 선택 현장의 확정 배분만 대상자별로 표시
   - 청구월·세전·세후·세금·비고·지급상태·입금일·증빙 확인
   - 전체 영업사원 통합 원장은 `/payroll/buyback-ledger`에서 회계 보조 화면으로 유지

정산대상자 관리로 바로 이동하는 버튼을 제공하고, 영업사원 기본 세후율은 대상자 디렉터리에 저장한다.

## 4. 데이터 연결 원칙

- canonical FK: `settlementTargetId = settlement_targets/{docId}`
- source key: `progress_claims/{siteId + yearMonth}`를 바이백 원천으로 사용
- 현장 원금은 대상자 수와 무관하게 현장·월별 한 번만 집계
- `office_income`은 외부 지급 대상과 분리해 사무실 귀속액으로 집계
- 과거 표시 보존: 배분 행에는 이름·유형·회사명을 스냅샷으로 유지
- 기존 호환: 기성 배분의 비사무실 `targetId`만 `settlementTargetId`의 fallback으로 읽음
- 금지: 지원현장 배분의 모든 `targetId`를 정산대상자 ID로 일괄 변환
- 지급상태와 기성문서 상태를 분리
- 확정 후 금액·세후조건·산식은 잠그고, 지급·증빙·정산대상자 재연결만 갱신
- 세후·세금은 원본 입력값이 아니라 계산 가능한 값으로 유지하고, 수기 모드만 세후 입력을 저장
- 확정 시 `allocations[]`도 snapshot에 복제

## 5. 단계적 마이그레이션

1. 정산대상자 유형 보존 버그 수정 및 영업사원 등록
2. 기성 배분에 additive 필드 추가 후 기존 문서는 호환 읽기
3. 현장별 워크북 현황과 현재 기성 편집을 연결
4. 원본 엑셀 가져오기 전 미리보기에서 시트명→정산대상자, 현장명→현장 ID를 검토 매핑
5. 매핑되지 않은 현장/수기 산식은 검토 큐로 남기고 자동 병합하지 않음
6. 월·현장·영업사원별 세전/세후/세금 합계를 원본과 대사한 뒤 전환
7. 음수 조정·회차 납입·대여금·임대료 보조표는 별도 원장으로 이관하고 합계 대사 후 연결

장기적으로 지급·증빙·수정 이력까지 회계 원장으로 사용하려면 `buyback_entries/{sourceKey}` 평탄 컬렉션을 두고 기성 배분과 이중 기록하는 구조가 적합하다. 이번 화면은 기존 기성 배분을 깨지 않는 additive 구조를 우선 적용한다.

## 6. 완료 기준

- 영업사원 유형을 생성·수정해도 유형과 기존 연결 필드가 보존된다.
- 바이백 행은 정산대상자 문서 ID로 연결된다.
- 75/25, 계산서 전액, 세후 직접입력 계산이 원 단위로 일관된다.
- 지급상태·예정일·입금일·증빙상태를 저장하고 다시 불러올 수 있다.
- 부분입금·입금완료·과입금의 실입금액과 잔액이 상태와 일치한다.
- 현장별 대장에서 미작성·미배분 현장을 포함해 월별 산정 상태를 확인할 수 있다.
- 같은 대상자가 여러 현장에 배분되어도 현장 행은 서로 분리되고 원금이 중복되지 않는다.
- 사무실 귀속, 외부 지급 세전·세후, 실입금, 미지급을 분리 확인할 수 있다.
- 대상자별 지급 상세에는 선택 현장의 확정 내역만 표시된다.
- 기존 기성/배분 문서는 새 필드가 없어도 정상 표시된다.
- 계산 단위 테스트, 타입 검사, 빌드, 로컬 브라우저 검증을 통과한다.
