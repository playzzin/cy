# 팀 메뉴 점검 및 평균경비 계산

## 범위와 상태

- 사용자 요청: 최근 팀 메뉴 오류 점검, 담당현장 공수와 타현장 지원 공수를 합친 공수당 경비 계산.
- 운영 데이터 접근·변경, 커밋, 배포 없음. 기존 미커밋 작업 보존.
- 아래 결함은 현재 코드에서 확인한 것으로 최근 이틀에 생긴 회귀라고 단정하지 않는다.

## 평균경비 구현

경비현황 화면에 팀 경비, 담당현장 공수, 다른현장 지원 공수, 합산 공수, 평균경비(원/공수)를 표시한다.

평균경비 = 기존 정산 반영 팀 경비 합계 / (해당 팀 작업자의 담당현장 공수 + 다른현장 지원 공수).

- 조회월의 작업일보 작업자 소속 스냅샷 기준. 현장 전체 공수나 다른 팀 공수는 포함하지 않는다.
- 동일 일보 ID 중복 제거. 다른 현장의 정상 분할 근무는 합산.
- 공수 0이면 평균 미표시. 일보 조회 실패 시 경고 및 평균 표 숨김.
- 분자에는 기존 경비 합계 정책(후청구 가산·차감 포함)을 유지.
- 소속 기록이 없는 레거시 행은 기존 일보 팀 기준으로 추정되므로 과거 원자료 확인 필요.
- 서로 다른 ID로 중복 저장된 일보는 정상 분할 근무와 구별할 근거가 없어 자동 병합하지 않음.

## 발견된 결함 — 이번에는 점검만 수행, 미수정

1. **높음: 장비 조회 실패 후 저장 허용**
   - TeamEquipmentStatusPage:473–498, 567–573.
   - 공용 DB 조회 실패 후 로컬/기본값 표시 상태에서도 저장 가능. 재현 시 0 수량 전체 저장 호출 발생.
   - 임시 운영 조치: 공용 DB 조회 경고가 보이면 저장하지 않고 재조회.
2. **높음: 팀별 저장이 전체 팀을 저장**
   - TeamEquipmentStatusPage:666–674.
   - 한 팀 저장 시 다른 팀의 미저장 변경도 payload에 포함되지만 해당 팀만 저장 완료 표시.
   - 전체 스냅샷 저장으로 동시 편집 덮어쓰기 위험도 있음. 실제 두 사용자 동시성 검증은 미실행.
   - 임시 운영 조치: 복수 팀 미저장 상태 및 동시 편집 피하기.
3. **중간: 과거 월의 종료 숙소 배정 누락**
   - TeamResourceDetailPage:539–549, 754–762.
   - 조회월과 겹쳐도 ended 상태를 먼저 제외. 과거 배정/월세 표시 누락.
4. **중간: 현재 차량·카드 배정이 과거 월에도 표시**
   - TeamResourceDetailPage:587–599, 633–645, 764–792.
   - 현재 마스터 배정을 선택 월 확인 없이 먼저 포함.
5. **낮음: 대시보드 월 누적 문구와 최근 30일 계산 불일치**
   - FieldRoleDashboardView:169–170, 210, 255.
   - 월초 이후 누적과 최근 30일은 다르므로 기준 정리 필요.

## 검증

- 평균경비 및 인접 경비 기능: 6개 테스트 묶음, 40개 테스트 통과. 부모 담당자가 직접 재실행 확인.
- 팀원 요청·경비 신청 기존 검증: 감사 담당자 보고 기준 4개 테스트 묶음, 23개 통과.
- 수정 후 npm run typecheck 통과.
- 브라우저 실제 데이터/E2E, 전체 프로젝트 검증 및 보안 Emulator 미실행.
- 최초 빌드는 도구 시간 초과로 결과 미확보. 재실행한 npm run build는 종료 코드 0으로 완료되었고 postbuild 기록 생성도 완료. 운영 배포는 하지 않음.
