# 엑셀 양식 변환기 완성도 개선 기획

작성일: 2026-09-29  
상태: 구현 반영 — 아래 현황 표는 기획 시점의 진단이며, 2026-09-30 구현·검증 결과는 `excel-converter-implementation.md`에 기록함

## 목표와 범위

사용자가 원본과 받을 양식을 올리고, 대화로 수정을 이어가며, 바뀐 내용과 근거를 확인한 뒤 제출할 엑셀을 완성한다.

우선 범위는 현재 지원하는 원본 1개와 받을 양식 1개의 변환이다. 노임명세서·위임장 같은 반복 업무를 기준으로 설계한다. 모든 엑셀 기능을 편집하는 범용 프로그램, 여러 사람의 동시 편집, 서버 파일 보관은 후속 범위로 둔다.

성공 기준은 기능 개수보다 다음 세 가지다.

- 사용자가 이번 요청으로 바뀐 내용을 설명할 수 있다.
- 잘못 요청했거나 화면을 벗어났을 때 작업을 복구할 수 있다.
- 미리보기에서 확인한 결과와 내려받은 파일의 값·계산·양식이 일치한다.

## 목표 사용 흐름

1. 원본과 받을 양식을 첨부한다. 파일 역할·시트·읽을 범위를 간단히 확인한다.
2. “이 양식으로 옮겨줘”라고 요청한다. AI가 처리한 단계와 남은 확인 사항을 보여준다.
3. 첫 결과가 나타나면 작성 건수, 제외된 데이터, 검증 결과를 요약한다.
4. 사용자가 “이 금액은 왜 이렇게 나왔어?”라고 물으면 원본 위치와 계산 근거를 설명한다. 설명만으로 결과 버전을 만들지 않는다.
5. 미리보기에서 대상 행 또는 셀을 선택하고 “이 부분만 바꿔줘”라고 요청한다. 선택 대상은 입력창 위에 표시한다.
6. 새 결과에서 실제 변경 부분을 강조한다. 이전 조건과 직접 수정한 값은 관련 요청이 없는 한 유지한다.
7. 원하는 결과를 내려받거나, 이전 결과에서 다시 수정을 이어간다. 보관을 선택한 작업은 다시 열 수 있다.

일반적인 수정 요청은 매번 확인 창을 거치지 않는다. 뜻이 모호하거나 지원하지 못하는 요청일 때 필요한 정보만 묻는다. 인원 제외·합산처럼 결과 범위가 달라지는 요청은 영향 건수와 차이를 눈에 띄게 보여준다.

## 우선순위와 완료 기준

| 순서 | 개선 항목 | 사용자가 얻는 변화 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 변경 비교와 근거 확인 | 무엇이 달라졌고 값이 어디에서 왔는지 확인 | 값 변경·행 이동·추가·제외를 구분하고, 항목을 누르면 해당 문서·시트·셀로 이동 |
| 2 | 설명과 수정 구분, 적용 조건 표시 | 질문은 설명으로 받고, 현재 규칙을 눈으로 확인 | 설명 요청은 새 파일을 만들지 않으며 10회 이상 후속 수정에서도 관련 없는 조건 유지 |
| 3 | 이전 결과부터 다시 수정 | 마음에 드는 결과를 출발점으로 재작업 | 선택한 버전의 계획·직접 수정·대화 문맥으로 새 결과 생성. 이후 버전도 보존 |
| 4 | 작업 복구 | 새로고침이나 재접속 후 이어서 작업 | 보관을 선택한 작업의 첨부·시트·대화·버전 복구, 저장 실패 시 복구 가능하다고 표시하지 않음 |
| 5 | 선택 영역을 대상으로 대화·직접 수정 | 긴 설명 없이 특정 부분만 고침 | 선택 범위 밖의 값 유지, 직접 수정 값의 후속 변환 보존, 수식·병합 영역 처리 검증 |
| 6 | 미리보기와 파일의 표현 일치 | 화면에서 검토한 결과를 안심하고 제출 | 날짜·금액·백분율·앞자리 0·줄바꿈의 대표 표시 사례를 실제 Excel과 대조 |

실제 AI 평가와 실패 복구 검증은 마지막에 몰아서 수행하지 않고 각 단계의 완료 조건에 포함한다.

## 화면 구성

상단에는 작업명, 저장 상태, 파일 관리를 둔다. 저장하지 않은 상태와 이 기기에 보관된 상태를 분명히 구분한다.

왼쪽 대화 영역은 요청·설명·결과가 시간순으로 쌓인다. 최신 결과는 간결하게 보여주고 상세 검사 내역은 펼쳐서 확인한다. 사용자가 이전 대화를 읽고 있으면 진행 상태 갱신 때마다 맨 아래로 강제로 이동시키지 않는다.

입력창 위에는 선택한 셀·행과 적용 중인 조건을 표시한다. 예: `선택: 2명` / `이름순 정렬` / `서명란 비우기`. 조건의 적용 범위와 제거 가능 여부를 구분한다. “여기만 바꿔줘”에 선택 대상이 없으면 대상을 묻는다.

오른쪽 미리보기에는 다음 기능을 배치한다.

- 상단: 보고 있는 결과 버전, 이 결과부터 수정, 선택한 결과 다운로드.
- 문서 도구: 원본·받을 양식·완성 결과, 시트·출력 문서 선택, 배율, 확대.
- 검토 도구: 변경된 항목, 확인할 문제, 현재 선택의 원본 근거.
- 문서 본문: 변경 표시와 문제 위치 표시. 색상만으로 구분하지 않고 표식과 설명을 함께 제공.

일반 노트북에서는 대화와 문서를 동시에 본다. 작은 화면에서는 대화·미리보기 전환으로 주요 작업을 빠르게 오가며, 두 화면의 입력값·선택·스크롤을 유지한다. 넓은 화면은 두 영역의 너비 조절을 지원한다.

## 주요 기능의 동작 규칙

### 변경 비교

셀 주소 비교와 데이터 항목 비교를 구분한다. 이름순으로 정렬했을 때 모든 값이 바뀐 것으로 표시하지 않고 “행 순서 변경”으로 표시한다. 원본 행의 식별 정보와 출력 값의 출처를 이용해 동일한 항목을 대응시킨다.

값 변경은 변경 전·후·변경 이유를 함께 보여준다. 출력 파일이 여러 개면 변경된 파일부터 찾을 수 있다. 필터로 제외한 데이터와 빈 줄·합계 줄처럼 읽기 과정에서 제외한 행은 다른 항목으로 집계한다.

### 대화 이해

요청을 설명, 변경, 확인 질문에 대한 답변, 지원하지 않는 작업으로 구분한다. 설명은 현재 결과와 검증 근거에 기반하고 결과를 변경하지 않는다.

정렬·필터·고정 문구 같은 적용 조건을 별도 상태로 유지한다. 긴 대화를 단순히 줄이는 것에 의존하지 않고 현재 유효한 조건, 이번 요청, 선택 범위를 전달한다. 취소하거나 대체한 조건은 다시 살아나지 않아야 한다.

검증은 전체 대화 어딘가에 비슷한 요청이 있었다는 이유로 새 변경을 허용하지 않는다. 이번 요청의 대상과 허용한 변경, 이전에 유지하기로 한 조건을 기준으로 검사한다.

### 버전과 되돌리기

각 결과에 원본·양식의 식별 정보, 변환 계획, 직접 수정 값, 부모 버전, 요청, 검증 결과를 함께 보관한다. 결과 파일만 교체하는 되돌리기는 피한다.

“이 결과부터 수정”을 누르면 선택한 버전이 수정 기준이 된다. 그 뒤에 만들어진 결과는 비교와 다운로드를 위해 유지한다. 어떤 결과를 보고 있고 어떤 결과에 수정을 적용하는지 일치시키거나 명확히 표시한다.

### 작업 복구

현재 저장 코드의 재사용 가능성을 먼저 검토하되, 채팅 세션과 버전 구조에 맞는 별도 저장 형식과 변경 절차를 정한다.

기본 제안은 사용자가 선택하는 “이 기기에 작업 보관”이다. 저장 위치·보관 기간을 표시하고, 파일 내용이 포함되는 점을 알려준다. 서버 동기화는 별도로 기획한다.

첨부 파일은 작업 내에서 중복 저장하지 않는다. 저장 용량 부족, 브라우저 저장 차단, 잘못된 저장 데이터, 계정 변경을 처리한다. 저장하지 않은 결과가 있을 때 새 대화·파일 교체·페이지 이탈로 사라지는 상황도 처리한다. 기존 사용자 선택에 따라 반복 확인을 줄인다.

### 선택 영역과 직접 수정

처음에는 셀 하나와 행 하나를 지원하고, 이후 열·여러 셀로 넓힌다. 선택 문맥에는 결과 버전·출력 문서·시트·셀·원본 행 대응 정보를 포함한다. 버전이나 문서가 바뀌면 오래된 선택을 해제하거나 안전하게 다시 대응시킨다.

직접 수정은 변경 기록에 포함한다. 정렬 이후에도 같은 사람·항목에 적용되어야 한다. 그룹 합산 등으로 대응이 모호해지면 임의로 다른 행에 적용하지 않는다. 수식 셀은 일반 값 입력과 구분하고, 병합 영역은 기준 셀을 대상으로 다룬다.

### 미리보기의 정확성

우선순위는 값과 표시 형식, 그다음 레이아웃이다. 날짜를 일련번호로 보이게 하거나 계좌번호의 앞자리 0을 잃지 않는지 확인한다.

화면 미리보기와 인쇄 미리보기의 범위를 구분한다. 이미지·도형·페이지 나눔을 지원하기 전에는 실제 Excel과 동일하다고 안내하지 않는다. 부분 갱신은 입력 중인 문장에 반응하는 기능이 아니라 요청이 적용·검증된 결과를 갱신하는 방식으로 유지한다.

## 구현 순서

1. 결과 버전의 계획·출처·검증 정보를 정리한다. 변경 비교, 되돌리기, 복구가 같은 기록을 사용하도록 기반을 맞춘다.
2. 변경 목록과 원본 근거, 경고 위치 이동을 제공한다. 결과 검토에 걸리는 시간을 줄이는 첫 배포 단위다.
3. 설명·수정 구분과 적용 조건 표시를 추가하고, 특정 버전부터 이어서 수정하는 흐름을 연결한다.
4. 작업 보관과 복구를 연결한다. 작은 화면 전환, 스크롤 유지, 입력 중 이탈 처리도 함께 개선한다.
5. 선택 영역을 대화에 연결한 뒤 직접 수정을 추가한다. 마지막으로 표시 형식·대용량 처리와 반복 양식 재사용을 확장한다.

각 단계는 독립적으로 검토 가능한 결과로 마무리한다. 일정은 1단계에서 기존 저장 구조·출처 정보 재사용 범위를 확인한 뒤 산정한다.

## 출시 전 검증

다음은 제안하는 통과 기준이며 현재 달성률을 뜻하지 않는다.

- 대표 파일 조합 20개 이상: 노임명세서, 개인별 위임장, 병합 셀, 여러 시트, 달라진 열 순서, 빈 값, 수식, 긴 한글, 앞자리 0을 포함한다.
- 연속 수정: 한 작업에서 10회 이상 요청하고 초기에 지정한 조건이 유지되는지 확인한다. 조건 취소·변경도 포함한다.
- 설명 요청: 결과 버전과 파일 내용이 바뀌지 않는지 확인한다.
- 변경 비교: 단순 정렬을 값 변경으로 표시하지 않고 실제 수정·추가·제외를 구분한다.
- 실패 복구: 네트워크 실패, 중단 후 늦은 응답, 새 대화, 새로고침, 저장 용량 부족에서도 이전 완성 결과가 훼손되지 않는다.
- 파일 대조: 저장된 엑셀을 다시 열어 행 수·총액·직접 수정·병합·수식과 미리보기를 대조한다.
- 실제 AI: 가상 또는 비식별 평가 파일로 응답을 반복 측정한다. 모의 응답 검증과 실제 AI 검증을 별도로 기록한다. 외부 전송 실행은 기존 작업 규칙을 따른다.
- 성능: 대표 파일로 처음 결과가 나오는 시간, 단순 수정 시간, 화면 반응, 메모리 사용을 측정하고 기준선을 정한다. 현재 허용 최대치가 곧 쾌적한 처리 성능을 의미하지는 않는다.

운영 지표는 첫 결과 생성 성공률, 요청 의도 반영률, 불필요한 추가 질문 비율, 파일 대조 오류 수, 작업 복구 성공률, 결과 생성 시간의 중앙값과 상위 지연 구간으로 잡는다. 측정 기록에는 원본 값이나 개인정보를 담지 않는다.

## 첫 개선 묶음 제안

가장 먼저 **변경된 부분 표시 + 원본 근거 확인 + 결과 버전의 계획 보관**을 구현한다. 사용자가 결과를 검토할 수 있는 기능을 먼저 완성하면서, 이후의 되돌리기·선택 수정·복구가 같은 기반 위에서 동작하도록 한다.

이후 **설명과 수정의 구분 + 이전 결과부터 수정 + 작업 복구**를 연결한다. 이 단계까지를 일상 업무에 반복적으로 사용할 수 있는 첫 완성판의 기준으로 삼는다.
