# Excel 변환기 안정성 개선 검증

2026-09-30. 사용자 요청: 수식·함수·매크로까지 대화로 편집하는 변환기의 완성도 향상.

## 이번 변경

- 파일 구조 준비 → AI 편집 → 데이터 작성 → 결과 검사 전체에 4분 제한을 적용했다. 취소 신호를 처리하지 않는 비동기 작업도 기다림을 종료하고, 늦게 도착한 응답은 결과에 반영하지 않는다. 30초 이상 기다리면 요청과 이전 결과가 유지됨을 안내한다.
- 중단한 요청을 입력창으로 복원한다. 시간 초과·연결 오류 후에도 이전 결과를 내려받고 같은 요청으로 재시도할 수 있다. 제한 시간 후 자동 수정 요청을 추가로 보내지 않는다.
- AI 전송 전후 및 VBA 문맥 준비 후 취소 상태를 검사한다. `Module1의 함수 수정`처럼 모듈 이름을 직접 부르는 요청도 VBA 편집으로 인식한다.
- 원문 문자열 치환표를 엄격히 복원한다. 따옴표 밖으로 이동하거나 다른 문구와 결합되거나 알 수 없는 문자열 참조는 결과 파일에 쓰지 않는다. 인라인 `Rem`과 이어지는 주석도 AI 입력에서 제외한다. 일반 문자열과 주석을 구분하는 기준은 Microsoft의 [Rem 문서](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/rem-statement)를 참고했다.
- 범위 수식을 채울 때 `Table1[A1]` 같은 표의 열 이름을 셀 주소로 이동하지 않는다. 일반 문자열의 `|`, 함수 이름, 외부 참조처럼 보이는 문구를 실행 수식으로 오인하지 않는다. 실제 외부 연결/DDE 제한은 유지한다.
- VBA 함수의 여러 줄 선언과 한글 이름을 처리하면서 숨은 프로시저 속성을 선언 끝에 보존한다. 속성에 `$1` 같은 문자열이 있어도 치환하지 않는다.
- 다른 시트나 오래된 결과에서 선택한 주소를 현재 변환 시트에 잘못 적용하지 않는다.

## 적용 및 남은 검증 범위

- 안정성 개선 후 사용자의 추가 배포 요청으로 아래 운영 배포까지 완료했다. Git push와 서버 기능·권한 설정 재배포는 하지 않았다.
- 4분 제한은 브라우저가 기다림을 중단하는 장치다. 이미 서버에 전달된 AI 호출의 실행·과금을 되돌리지 않는다. 긴 동기 계산 중에는 브라우저 이벤트 루프가 다시 동작한 뒤 취소가 반영된다.
- VBA의 저장·재읽기와 지정된 가상 매크로 실행을 검증했다. 임의 VBA의 컴파일·실행 호환성 전체나 모든 Excel 함수의 브라우저 계산을 보증하지 않는다. 브라우저에서 매크로를 실행하지 않는다.
- 현재 변환 대상으로 선택한 시트의 편집이 기준이다. 여러 시트를 동시에 편집하는 기능, 잠기거나 서명된 VBA 프로젝트 편집, 새 프로젝트 컨테이너 생성은 별도 범위다.
- 최대 크기 파일의 장시간 부하, 다수 계정의 동시 사용 및 실제 고객 파일군 호환성은 이번에 측정하지 않았다. 가상 자료에서 확인한 품질을 전체 상용 환경의 보증으로 확대하지 않는다.
