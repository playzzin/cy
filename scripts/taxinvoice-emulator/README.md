# 발행리스트 저장소 통합 검증

`node scripts/taxinvoice-emulator/run.cjs`로 독립 Firestore 에뮬레이터를 시작하고 실제 `taxInvoiceListService`를 실행한 후 종료한다. 기존 Node 패키지, 공식 Firebase 에뮬레이터 JAR와 Java를 사용한다. 실행 중인 서비스가 18086 포트를 사용하면 중단한다. DB는 메모리에만 존재한다.

- 프로젝트는 `demo-taxinvoice-issue-e2e`, 주소는 `127.0.0.1:18086`으로 고정한다.
- 운영 Firebase 설정, 자격 증명, `.env`, 업무 데이터를 읽지 않는다.
- 이 폴더의 규칙은 에뮬레이터 시험 전용이며 운영 규칙 검증이나 배포를 대신하지 않는다.
- 실제 SDK와 저장 코드를 사용해 동시 저장/삭제, 451건 부분 처리와 재시도, 연결 차단/복구, 중복 이월, 문서 ID를 검증한다.
- `disableNetwork`만으로 트랜잭션 장애를 가정하지 않고, 실패 시험은 로컬 TCP 프록시 연결을 차단한다.
- 결과는 `artifacts/audits/taxinvoice-emulator-results.json`에 저장한다.

## 브라우저 검증

`node scripts/taxinvoice-emulator/run.cjs --ui` 실행 후 `http://127.0.0.1:3097/`을 두 창에서 연다. Ctrl+C로 시험 화면과 에뮬레이터를 종료한다. 실제 페이지, 저장 서비스, 확인창, 엑셀 내보내기를 사용한다. 상단 메뉴 및 현장 마스터 조회만 시험용으로 대체한다. 화면의 외부 연결은 CSP로 차단한다. 전체 앱 로그인/권한 검증 범위는 포함하지 않는다.

1. A창에서 A업체 공급가를 250으로 저장한다. 이전 값 100을 가진 B창에서 350으로 저장하면 충돌이 표시되어야 한다.
2. B창에서 내 입력 유지를 선택한 뒤 다시 저장한다. A창에서 A업체를 삭제하면 250/350 충돌이 표시되어야 한다. 최신 내용 확인만으로 행이 삭제되지 않아야 한다.
3. A창에서 B업체를 삭제한다. 두 창 각각 같은 전월 이월 항목을 가져와도 이번 달 목록은 A업체와 이월업체 두 건만 남아야 한다.
4. 이월업체를 검색해 엑셀을 내려받는다. 검색 해제, 팀 정렬, 이전 달/다음 달 이동 후 A업체 350과 이월업체 500이 유지되는지 확인한다.
5. 다운로드 파일을 `node scripts/taxinvoice-emulator/verify-ui.cjs "다운로드 파일 절대 경로"`에 전달한다. 저장소 값과 실제 파일의 행 수/금액을 비교하고 결과를 기록한다.

브라우저 조작은 사용자 환경의 브라우저 도구로 수행하며, 위 검증기는 화면 조작을 자동으로 수행하지 않는다.

## 로그인·권한 검증

`node scripts/taxinvoice-emulator/run-permissions.cjs "검증할 Firestore 규칙 파일 절대 경로"`로 공식 Auth/Firestore 에뮬레이터에서 검증한다. 기본값은 작업본의 `firestore.rules`이며, 운영과 비교할 때에는 읽기 전용으로 받은 실제 배포 규칙 사본을 전달한다. 운영 규칙을 배포하거나 변경하지 않는다.

실제 SDK 로그인/로그아웃, 관리자·회계·급여 활성 계정의 조회/저장/삭제, 승인 대기·정지·프로필 없는 계정의 차단, 451건 일괄 저장/삭제를 확인한다. 현재 활성 현장 계정까지 조회를 허용하는 기존 정책은 제외 요청에 따라 변경하지 않고 관측 결과만 기록한다. 모든 계정·자료는 `demo-taxinvoice-issue-e2e`의 메모리 저장소에만 생성한다.
